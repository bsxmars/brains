# Связь объектов: наблюдатель, посредник, цепочка обязанностей

`patterns/communication` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** три паттерна про то, кто кого зовёт: рассылка подписчикам, посредник со сценарием, цепочка, где каждый решает, звать ли следующего.
- **Зачем:** снизить связность: обработчик формы не знает потребителей заявки.
- **Как работает:** наблюдатель — синхронный цикл по подписчикам; посредник держит порядок шагов в одном месте; цепочка — текущее звено само вызывает следующее или останавливает запрос.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Наблюдатель встроен дважды — `EventTarget` и `EventEmitter`; реализации по-разному переживают изменение списка во время рассылки → «раздел Наблюдатель».
- Карта «имя события → данные» ловит опечатку в имени и не те данные; отписка — возвращаемая функция → «раздел Наблюдатель».
- Рассылка не ждёт `async`-слушателей → «раздел Наблюдатель».
- Нужна очерёдность шагов — посредник, а не рассылка → «раздел Посредник».
- Шина не помнит прошлого, стор помнит последнее значение → «раздел Посредник».
- Middleware: массив функций и `compose`, «луковица» с `await next()` → «раздел Цепочка обязанностей».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Книжный `notify` по массиву: отписка во время рассылки пропускает соседа; лечится копией `[...observers]`.
- `a.next(b).next(c)` — это `c`: цепочка теряет начало, проверка доступа пропущена.
- `next()` дважды выполняет хвост дважды; `next()` без `await` — ответ уходит раньше контроллера.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `EventEmitter` раздаёт по снимку; `EventTarget` снятого пропускает сразу; `Set` вызывает добавленного в ту же рассылку → «раздел Наблюдатель».
- `EventTarget` в Node 26 вызывает добавленного во время рассылки, Chromium — нет → «раздел Наблюдатель».
- Исключение в слушателе `EventTarget`: рассылка идёт дальше, в Node — бросок в `process.nextTick`, `try` не ловит → «раздел Тонкие места».
- `MaxListenersExceededWarning` на 11-м слушателе → «раздел Тонкие места».
- Дважды подписанная функция: `EventEmitter` зовёт дважды, `EventTarget` — раз → «раздел Тонкие места».
- В Koa `compose` есть проверка `next() called multiple times` → «раздел Цепочка обязанностей».

</details>
