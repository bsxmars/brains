# React изнутри: хуки и контекст

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- Список ячеек связывает последовательные вызовы хуков между рендерами. Dependencies и lanes описывают другую работу: контекст и необходимость обхода.
- Memo промежуточного компонента не отменяет обновление читателя контекста внизу дерева.
- UseSyncExternalStore проверяет согласованность снимка, чтобы конкурентный render не опубликовал смесь состояний внешнего стора.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- «Каркас» и «Диспетчер»: bailout, собственная работа, childLanes и выбор реализации хука.
- «Ref, memo, callback»: ячейка и сравнение зависимостей через Object.is.
- «State и reducer»: очередь, eager-проверка и случай того же значения.
- «Контекст»: подписки на всё значение и обход сквозь memo.
- «Внешний стор»: tearing, согласованный снимок и подписка.

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- UseContext подписывает на значение контекста целиком, а не только на прочитанное поле объекта.
- Новый объект value меняет контекст даже при равных полях; стабильность ссылки имеет смысл, если значение не изменилось.
- UpdateProvider — имя функции мини-версии. В React 19.3 ленивое сравнение значений связано с propagateParentContextChanges.
- GetSnapshot должен возвращать стабильный снимок при отсутствии изменения.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Учебный renderer и React могут получить одинаковую согласованную страницу через разное число commit.
- Состав ячеек useContext и useSyncExternalStore проверяется по установленному React, а не выводится из имени хука.
- Таблица «Против React» отмечает оптимизации и упрощения мини-версии.

</details>
