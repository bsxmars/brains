# Сигналы: третья модель реактивности

`frameworks/signals` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** ячейка со значением, версией и списком читателей; чтение внутри вычисления и есть подписка.
- **Зачем:** будить только зависящие места, а не перезапускать компонент целиком, как React.
- **Как работает:**
  1. `set` поднимает версию и толкает вниз только пометку «грязно» (push), ничего не считая.
  2. Эффекты запускаются после того, как пометка обошла весь граф.
  3. Эффект тянет значения вверх (pull): узел пересчитывается, только если версия источника разошлась с запомненной.
  4. Порядок сам выходит топологическим, непрочитанное не считается.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Наивный push на ромбе даёт эффекту несогласованную пару и лишний прогон → «раздел Ромб и глитч».
- Эффект — `computed` без читателей, встаёт в очередь; пакет откладывает её слив → «раздел Эффект и пакет».
- Компонент выполняется один раз, на каждое изменчивое место — свой эффект → «раздел DOM без VDOM».
- React перезапускает компонент с потомками, Vue — render-эффект компонента, сигналы — эффект узла → «раздел Vue и React».
- TC39 стандартизирует граф, но не эффекты → «раздел TC39».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Чтение в теле компонента (вне эффекта) застывает: изменчивое место должно быть функцией.
- Мутация массива внутри сигнала никого не будит: сравниваются ссылки. У Vue `ref` глубокий.
- Наивная реализация верна на цепочке, ломается только на ромбе. `batch` откладывает эффекты, не значения.

</details>
