# Server Components изнутри

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- RSC определяют, какой код остаётся на сервере; SSR формирует первоначальный HTML. Эти механизмы можно применять вместе.
- Flight переносит результат серверного дерева и ссылки на клиентские модули. Серверный модуль не становится частью клиентского bundle из-за передачи результата.
- Граница use client требует поддерживаемых сериализуемых значений; серверная функция проходит специальной ссылкой.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- «Не другой SSR»: Flight, HTML и интерактивное дерево браузера.
- «Формат потока»: сквозной Page, строки и ссылки между частями результата.
- «Своими руками»: исходник ограниченного сериализатора перед исполняемым демо.
- «Граница use client» и «Серверные функции»: допустимые props и вызов по идентификатору.
- «Async, Suspense, cache»: досылка результата и повторное использование вычисления в серверном render.

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Клиентский компонент может исполняться на сервере при SSR: client не означает «только браузер».
- Date, Map и Set поддерживаются; запрет на экземпляры относится к неподдерживаемым пользовательским классам.
- Ссылка на серверную функцию не отменяет серверную проверку входных данных и прав.
- Порядок готовности частей потока не равен порядку компонентов в исходнике.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Текстовый снимок Flight относится к React 19.3 и этому примеру; полный протокол шире учебного подмножества.
- Таблицы props и ошибок получены настоящими сервером и клиентом, а демо исполняет мини-сериализатор.
- Cache из React повторно использует вызов в области серверного render; это не постоянный кеш данных приложения.

</details>
