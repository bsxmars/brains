# React изнутри: свой рендерер и хуки

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- Учебный renderer воспроизводит часть механизмов React; совпадение сценариев не делает его исходником React.
- Элементы описывают результат; фиберы хранят связи и состояние работы. Current опубликован, work-in-progress остаётся черновиком до commit.
- Render допускает паузы и отказ от черновика. Commit публикует завершённый результат, поэтому render должен быть чистым.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- «Элемент» и «Файбер и цикл»: объект результата и обход child/sibling/return.
- «Две фазы»: черновик, принятый результат и host-операции.
- «Сверка»: сохранение по типу/key и lastPlacedIndex.
- «Хуки» и «Батчинг»: учебный массив ячеек и одна запланированная микрозадача.
- «Эффекты», «Всё вместе», «Против React»: порядок, исполняемая модель и границы совпадения.

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Массив хуков — упрощение; у React связанные списки и дополнительные проверки порядка.
- Планирование useEffect отдельной задачей — решение мини-версии, не гарантия React относительно paint.
- Прерванный render может повторно вызвать компонент без публикации результата.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- В перестановке [a,b,c] → [c,a,b] правило lastPlacedIndex учебной версии и React перемещает a и b.
- Логи модели и React сопоставляются на одинаковых сценариях; демо использует host-модель, а не заменяет React на странице.
- Подключение к DevTools вынесено в раскрываемый исходник.

</details>
