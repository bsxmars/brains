# Роутер изнутри: от адреса до экрана

`frameworks/router` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** связь адреса и экрана SPA в обе стороны без загрузки документа.
- **Зачем:** документ один на сессию, а адрес должен работать как настоящий: копироваться, «назад», новая вкладка.
- **Как работает:** забирает клик, меняет адрес через History API → находит маршрут по весу и цепочку `matched` для `<RouterView>` → guards в жёстком порядке → ждёт код и данные.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- `pushState` молчит, `popstate` — только на ход по истории и смену якоря → раздел «История вкладки».
- Одно событие `navigate` на все переходы, браузер сам говорит, можно ли перехватить → раздел «Navigation API».
- Забирать клик, только если браузер сменил бы документ в этой вкладке на свой сайт; переход — ссылка, не `div @click` → раздел «Перехват клика».
- Порядок в массиве не важен: сортировка по весу, при равенстве — по объявлению → раздел «Ранжирование».
- `children` → плоский список; ребёнок с пустым путём встаёт перед родителем → раздел «Вложенные маршруты».
- Данные в компоненте — водопад; старт в `beforeEach` — самый быстрый → раздел «Ленивые маршруты и данные».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `push` при отмене не бросает — проверять `isNavigationFailure`.
- `return Promise.all(…)` из guard: массив = адрес, переход молча становится «уже здесь».
- При смене `:id` `beforeEnter` молчит, компонент не пересоздаётся.

</details>
