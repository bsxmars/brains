# Роутер изнутри: от адреса до экрана

- Клиентский роутер связывает URL и экран приложения, сохраняя один документ. Адрес должен работать при переходе по ссылке, обновлении страницы и движении назад или вперёд.
- Переход включает сопоставление маршрута, проверки доступа, загрузку нужного кода и подтверждение нового состояния. Не каждый начатый переход обязан завершиться публикацией экрана.
- `pushState` меняет запись истории без полной загрузки документа. При переходе по истории адрес уже изменён браузером, поэтому отмена может потребовать восстановления истории.
- Загрузка маршрута может устареть, если пользователь начал следующий переход. Отмена запроса и проверка актуальности результата защищают разные участки этого процесса.
- Клиентская проверка маршрута не является серверной авторизацией. Отдельно настройте выдачу начального документа по прямому адресу, обработку ошибок и поведение прокрутки.
