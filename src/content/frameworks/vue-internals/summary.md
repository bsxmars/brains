# Vue 3 изнутри: своя реактивность

`frameworks/vue-internals` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** реактивность Vue, собранная руками в шесть шагов и сверенная тестом с Vue 3.5.
- **Зачем:** у каждой «странности» реактивности есть строка-причина.
- **Как работает:** `Proxy` перехватывает чтение (`track` пишет `activeEffect` в таблицу `WeakMap → Map → Dep`) и запись (`trigger` будит подписчиков) → эффект перед запуском стирает связи и собирает заново → версии `Dep` не дают будить зря → `scheduler` ставит задание в очередь, которая сливается одной микрозадачей.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- `Reflect` с `receiver`, кеш прокси, ленивая вложенность, различие «добавил/изменил» → «раздел reactive».
- Обратная ссылка `deps`, `ITERATE_KEY` для перебора, обход копии подписчиков → «раздел track и trigger».
- Очистка связей перед запуском, `prev` для вложенных, флаг `running` против самоперезапуска → «раздел effect».
- `ref` — коробка со своим `Dep`; `shallowRef` не оборачивает значение → «раздел ref».
- `computed` ленив, кеширует, версия растёт только при новом значении; два прохода `notify` против глитча → «раздел computed».
- Дедупликация, сортировка по `id`, `nextTick` = промис слива → «раздел Планировщик».
- Настоящий 3.5: узлы `Link`, `globalVersion`, коллекции → «раздел Vue 3.5 иначе».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Обход живого `Set` встречает эффект снова; без копии и проверки версий — вечный цикл без ошибки.
- `target[key]` вместо `Reflect.get(…, receiver)` ломает только геттеры; без кеша прокси `state.user !== state.user`.
- Вложенный `effect` плодится на каждом прогоне внешнего; `!==` вместо `Object.is` будит на `NaN`.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `ITERATE_KEY` будится только на `'add'`/`'delete'` → «раздел track и trigger».
- Порядок `sync → pre → post → nextTick` → «раздел Планировщик».
- Вне компонента Vue задания `pre` не сортирует (порядок записи), мини — по `id` → «раздел Планировщик».
- `prepareDeps`/`cleanupDeps` с версией `-1` → «раздел Vue 3.5 иначе».
- У `Map` смена значения будит `size`/`values()`, но не `keys()` → «раздел Vue 3.5 иначе».

</details>
