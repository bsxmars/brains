# Реактивность Vue

`frameworks/vue-reactivity` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** если функция во время работы прочитала реактивное значение — она от него зависит; Vue сам это замечает.
- **Зачем:** не объявлять зависимости вручную.
- **Как работает:**
  1. `Proxy` перехватывает чтение → `track` записывает связь на текущий `activeSub`.
  2. Запись → `trigger` повышает версию и будит подписчиков.
  3. Связи задаёт выполнение: неподтверждённые за прогон удаляются.
  4. Эффекты компонентов идут в очередь, которая разбирается одной микрозадачей до кадра.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- `Proxy` видит новые и удалённые ключи, поэтому `Vue.set` удалён → «раздел Модель».
- `ref` по умолчанию: у него нет операции, тихо теряющей реактивность → «раздел Модель».
- Перехват дорог и вне эффекта; данные не для экрана держат через `markRaw`/`shallowRef` → «раздел Модель».
- `computed` ленив и будит подписчиков, только если значение изменилось → «раздел Граф».
- Три режима `flush` и `nextTick`; повторы схлопываются на трёх уровнях → «раздел Планировщик».
- Девять причин «не обновляется», шесть «слишком часто» → «раздел Ловушки».
- Сами останавливаются только эффекты, созданные синхронно в `setup()`/хуке; `effectScope` → «раздел Жизнь эффекта».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- После `await` чтения не записываются, а созданный эффект — ничей и утекает.
- Деструктуризация фиксирует значение; `toRaw` для записи мимо ловушки; `raw !== proxy` в сравнениях.
- `push` внутри эффекта не зацикливается, но эффект молча пропускает своё изменение.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Чтение через `reactive`: ×8 вне эффекта, ×11 внутри; память ×2.6 → «раздел Модель».
- Пять ловушек: `get`, `set`, `deleteProperty`, `has`, `ownKeys` → «раздел Модель».
- Порядок: `sync → pre → рендер → post → onUpdated → nextTick` → «раздел Планировщик».
- Флаги дедупликации `NOTIFIED`, `QUEUED`; `computed` не будит зря с 3.4 → «раздел Планировщик», «раздел Граф».
- 3.5: `{ deep: 2 }`, `pause()`/`resume()`, `onWatcherCleanup` до первого `await` → «раздел Ловушки», «раздел Жизнь эффекта».

</details>
