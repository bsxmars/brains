# Vue 3 изнутри: рендерер и patch

<details>
<summary><b>Ядро</b> — сохранить узлы, изменить порядок</summary>

- Patch сопоставляет старые и новые VNode по type и key. Совпавший узел обновляется, другой заменяется. Рендерер отдаёт операции хосту: в браузере это DOM, в учебном стенде — журналирующее дерево.

</details>

<details>
<summary><b>Карта</b> — от VNode к списку</summary>

- [VNode](/frameworks/vue-patch-internals/#s1): описание узла, shapeFlag, patchFlag и ссылка el на хост.
- [Mount и patch](/frameworks/vue-patch-internals/#s2): создать, обновить, заменить или снять поддерево.
- [Без ключей](/frameworks/vue-patch-internals/#s3): сопоставление по позиции сохраняет состояние позиции, а не элемента данных.
- [С ключами](/frameworks/vue-patch-internals/#s4): совпавшие края, быстрый остаток, карта середины и LIS.

<details>
<summary><b>Подвох</b> — идентичность и обещания</summary>

- Ключ по индексу привязывает состояние к позиции. Дубликаты ключей нарушают сопоставление; dev-предупреждение не исправляет результат.
- LIS сохраняет взаимный порядок узлов, а не их экранные координаты: вставки вокруг C и D могут сдвинуть их без отдельного move.
- Флаг патча — обещание компилятора. Неверный флаг оставляет пропущенное поле устаревшим.
- Проход справа налево позволяет вставлять перед уже установленным правым соседом.

</details>

<details>
<summary><b>Детали</b> — каноническая перестановка</summary>

- ABCDEFG → ABECDHFG: после краёв остаётся CDE → ECDH. Карта старых индексов + 1 — [5, 3, 4, 0]. C и D образуют LIS; H создаётся перед F, E переносится перед C. Для этих существующих узлов достаточно одного переноса.

- [Демо](/frameworks/vue-patch-internals/#s5) исполняет учебный рендерер. Его операции сравниваются с Vue 3.5.42 на том же хосте. Совпадение журналов не измеряет время DOM, layout или paint.

</details>
