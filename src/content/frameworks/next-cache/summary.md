# Слои кеша в Next.js: от fetch до роутера

`frameworks/next-cache` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** четыре кеша друг за другом: склейка запросов в рендере, кеш данных, кеш маршрута (снимок страницы), кеш роутера во вкладке.
- **Зачем:** статика быстрая, бэкенд спрашивают редко; цена — «почему не обновилось» означает «какой из четырёх держит старое».
- **Как работает:** вкладка спрашивает кеш роутера → промах: сервер, кеш маршрута → рендер: каждый `fetch` спрашивает кеш данных → одинаковый `fetch` в том же рендере не уходит никуда.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Одинаковые `fetch` в одном рендере уходят раз; не-`fetch` — через `cache()` из React → «Запрос в рендере».
- Кеш данных на диске, общий для всех; опции `fetch` решают, что хранить → «Кеш данных».
- Статика и ISR: срок — не таймер, первый после срока получает старое → «Кеш маршрута».
- Три функции сброса различаются тем, получит ли следующий старое или свежее → «Инвалидация».
- Префетч, переходы без запроса, «назад» из памяти; вебхук до вкладки не доходит → «Кеш роутера».
- Отлаживать сверху вниз: перезагрузка → `x-nextjs-cache` → дошло ли до бэкенда → «Модель четырёх слоёв».
- `cacheComponents`: кешируется только помеченное, остальное динамическое за `<Suspense>` → «'use cache'».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `fetch` без опций на статической странице застывает при сборке «навсегда»; пересборка без очистки `.next/cache` данные не обновляет.
- Одна строка `await cookies()` делает маршрут динамическим; свой `signal` выключает склейку.
- `revalidatePath` сбрасывает и данные страницы.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `x-nextjs-cache`: `HIT`, `STALE`, `MISS`, у динамики заголовка нет → «Кеш маршрута».
- До 15-й `fetch` без опций кешировался; `staleTimes.dynamic` 30 → 0 с → «Кеш данных», «Кеш роутера».
- `revalidateTag(tag, 'max')` → `STALE`; `{ expire: 0 }` → `MISS`; `updateTag` только в server action, сбрасывает кеш роутера; мягкие теги `_N_T_` → «Инвалидация».
- `cacheLife`: `stale`/`revalidate`/`expire`, профили; `◐` частичный пререндер → «'use cache'».

</details>
