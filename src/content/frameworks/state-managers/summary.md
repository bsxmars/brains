# Стейт-менеджеры изнутри

`frameworks/state-managers` · выжимка обновлена 2026-11-12.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** стор — переменная с состоянием плюс набор подписчиков, которых зовут при изменении.
- **Зачем:** вынести общие данные из компонентов, не будя всех на каждое изменение.
- **Как работает:** Redux после `dispatch` уведомляет подписчиков; Zustand сначала сравнивает ссылку состояния. Дальше селектор и фреймворк решают, изменился ли снимок компонента. В Pinia реактивные зависимости собирает Vue. Уведомление, проверка и рендер — разные шаги.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Стор сравнивает одну ссылку, не содержимое: новый объект с тем же значением — уведомление → «раздел Стор».
- Мутация в reducer прячет изменение от сравнения ссылок; Immer в Toolkit копирует только путь к изменённому полю → «раздел Redux».
- Селектор вызывается на каждое уведомление, слушатель — только при новом куске; `shallow` сравнивает по полям → «раздел Селектор».
- В Zustand 5 селектор — это `getSnapshot` в `useSyncExternalStore`, сравнивает React → «раздел Zustand».
- Pinia: запись того же примитива не планирует обновление, синхронные записи до одного сброса очереди объединяются → «раздел Pinia».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Селектор, строящий новый объект (в т.ч. `.map`/`.filter`), в Zustand 5 — бесконечный цикл и падение всего дерева; в Zustand 4 и `useSelector` — лишний рендер. Лечение: `useShallow` или селектор на поле.
- `useApp()` без селектора читает весь снимок: новый корень может дать обновление, даже если нужное человеку число осталось прежним.
- Деструктурированное число Pinia теряет связь с полем. Деструктурированный объект остаётся реактивным, но не отслеживает замену родительского поля; `storeToRefs` сохраняет эту связь.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Учебный Zustand пропускает `set((s) => s)`; Redux уведомляет и на незнакомое действие. Redux фиксирует снимок подписок на dispatch → «раздел Redux».
- Объектный селектор: 5 вызовов, 4 слушателя; с `shallow` — 2 → «раздел Селектор».
- Цикл: «Maximum update depth exceeded» (прод — #185) → «раздел Zustand».
- RTK: состояние заморожено, проверка мутаций только в разработке → «раздел Redux».
- `$subscribe`: по умолчанию раз за очередь, `flush: 'sync'` — на каждую запись → «раздел Pinia».

</details>
