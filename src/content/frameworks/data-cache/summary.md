# Кеш данных на клиенте: TanStack Query и SWR

`frameworks/data-cache` · выжимка обновлена 2026-11-12.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** стор, который сам ходит в сеть: компонент подписывается на ключ, кеш решает, идти ли на сервер.
- **Зачем:** серверные данные — копия, стареет сама и нужна многим компонентам; без кеша — дубли запросов, расходящиеся копии, ручные флаги.
- **Как работает:** ключ определяет запись кеша; наблюдатели одного ключа разделяют запрос в пути. Данные и состояние запроса независимы. Устаревшая копия может оставаться на экране, а повод и настройки обновления решают, когда запрашивать новую.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Две оси: «есть ли данные» и «идёт ли запрос» → «раздел Кеш по ключу».
- Срок свежести считают от ответа, срок хранения неиспользуемой записи — от ухода последнего наблюдателя. Истечение staleTime само по себе запрос не запускает; гидратация с сервера → «раздел Свежесть и сборка мусора».
- Обновление при фокусе и возврате сети, повторы с растущей паузой → «раздел Фокус и повторы».
- Оптимистичная запись, откат, сверка → «раздел Мутации».
- Неизменившиеся части ответа сохраняют старые ссылки → «раздел Структурное разделение».
- SWR: окно дедупликации вместо свежести, нет сборки мусора → «раздел SWR».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- При нулевом staleTime новое монтирование может запросить данные снова, но уже выполняющийся запрос дедуплицируется. Параметр queryFn, забытый в ключе, склеивает разные данные в одну запись.
- Оптимистичную запись может затереть старый фоновый ответ. cancelQueries предотвращает применение ответа; сеть прерывается, если queryFn передал signal в fetch.
- На сервере `QueryClient` — на каждый запрос, иначе данные пользователей смешаются.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `status`: `pending`/`success`/`error`; `fetchStatus`: `fetching`/`idle`/`paused` → «раздел Кеш по ключу».
- `staleTime` 0, `gcTime` 5 мин (на сервере бесконечный) → «раздел Свежесть и сборка мусора».
- 3 повтора, пауза `min(1000×2^n, 30000)`; `networkMode: 'online'` → «раздел Фокус и повторы».
- `onMutate` → `onError` → `onSettled`; у мутаций `retry: 0` → «раздел Мутации».
- Учебная шкала 2 с staleTime и 4 с gcTime показывает два независимых отсчёта. `replaceEqualDeep`, `notifyOnChangeProps` → «раздел Структурное разделение».
- `dedupingInterval` 2 с, `focusThrottleInterval` 5 с, `errorRetryInterval` 5 с → «раздел SWR».

</details>
