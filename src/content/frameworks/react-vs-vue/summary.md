# React против Vue

`frameworks/react-vs-vue` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** две модели обновления на одной задаче, сравнённые по счёту работы, не по времени.
- **Зачем:** понять, кто решает, что пересчитывать, и чем за это платят.
- **Как работает:**
  1. React: `setState` помечает фибер, пересчитывается всё поддерево; лишнее отсекает автор через `memo` и стабильные ссылки.
  2. Vue: чтения перехвачены, к записи известно, кто читал, — пересчитываются только они.
  3. React с `memo` везде и Vue дают одинаковые числа; правок DOM у всех поровну.
  4. React платит процессором и ручной работой, Vue — памятью графа и непрерываемой очередью.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Механизмы: подписка, тело против `setup`, прерываемость, tearing → «раздел Различие».
- Демо трёх вариантов на трёх действиях с разбивкой по узлам → «раздел Одна задача».
- Работа React без `memo` растёт со списком; стор с подпиской в листе делает обе модели точечными → «раздел Цена».
- Кеш обработчиков — свойство компилятора шаблонов, только для `v-on` → «раздел Перенос».
- `onMounted` по таймингу — `useLayoutEffect`, не `useEffect` → «раздел Перенос».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Стрелка через `:prop` во Vue ломает оптимизацию, как в React без `useCallback`.
- `takeRecords()` после `await` даёт ноль: записи забрала микрозадача колбэка.
- Профайлеры фреймворков вырезаны из продакшена.

</details>
