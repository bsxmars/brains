# React против Vue

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- Обе модели могут вызвать функции компонентов, не меняя DOM: вычисление и правка документа — разная работа.
- React начинает с помеченного фибера и обходит дерево; стабильные элементы, memo и отсутствие собственной работы дают пропуски.
- Vue записывает зависимости чтения и будит подписанные эффекты; компилятор и renderer дополнительно сокращают работу.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- «Различие»: где хранится знание о зависимости и какие проверки доступны при обновлении.
- «Одна задача»: настоящие React и Vue, общий исходник задачи, счётчики вызовов и правок DOM.
- «Цена»: масштаб списка, стор с подпиской в листе и память графа.
- «Перенос»: компиляция обработчиков и порядок жизненного цикла.

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Одинаковые числа на одной задаче не доказывают равную скорость или равный расход памяти.
- Vue обычно обновляет очередь в микрозадаче; React планирует работу в зависимости от lanes, в том числе задачей Scheduler.
- MutationObserver доставляет записи микрозадачей: takeRecords после await может увидеть пустую очередь.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Исторический снимок памяти описывает свою версию и нагрузку; стоимость графа считается сверх уже учтённого proxy.
- Число MutationRecord зависит от разбиения текста: добавление строки даёт три записи у React и две у Vue в показанном примере.
- В демо React с memo и Vue сокращают число вызовов на счётчике до двух при одной правке DOM.
- Проп callback с новой ссылкой и обработчик v-on имеют разные возможности оптимизации компилятором.

</details>
