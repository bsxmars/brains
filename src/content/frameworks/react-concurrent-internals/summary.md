# React изнутри: конкурентность и lanes

`frameworks/react-concurrent-internals` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** у каждого обновления есть полоса — один бит; рендер берёт одну полосу за раз, и более срочная выбрасывает начатое дерево.
- **Зачем:** чтобы ввод не залипал, пока рендерится тяжёлое несрочное.
- **Как работает:**
  1. `setState` поднимает бит своей полосы в `pendingLanes` корня.
  2. `getNextLanes` берёт младший бит — самый срочный.
  3. Планировщик режет рендер на кванты и отдаёт поток браузеру.
  4. Пришла полоса срочнее — рендер заново с корня; очередь цела, потому что её чистит коммит.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Маска отвечает про множество приоритетов одной операцией → «раздел Полосы».
- Планировщик — отдельный пакет со своими приоритетами; срочная полоса идёт микрозадачей мимо него → «раздел Планировщик».
- Число вызовов компонента не определено — отсюда чистота render-фазы и StrictMode как репетиция → «раздел Прерывание».
- Переход = «пометить полосой»; база хука переигрывает пропущенное в порядке вызовов → «раздел Переходы».
- Компонент бросает промис, граница показывает заглушку, пинг заказывает повтор; переход не прячет уже показанное → «раздел Suspense».
- У полосы есть срок, просроченная рендерится без уступок → «раздел Голодание».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Обновление из таймера/fetch (`DefaultLane`) переход **не** прерывает.
- `startTransition` выполняет колбэк сразу; после `await` полоса теряется — нужен ещё один `startTransition`.
- Просроченный переход идёт целиком — фриз на весь рендер.

</details>
