# Vapor Mode во Vue

`frameworks/vue-vapor` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** компиляция того же SFC без виртуального DOM: строка HTML для клонирования плюс эффекты, пишущие прямо в узлы.
- **Зачем:** убрать работу JS до DOM — ни вызова render, ни дерева VNode на каждое изменение. DOM-операций почти столько же.
- **Как работает:**
  1. `template(html)` разбирает строку один раз, дальше `cloneNode(true)`.
  2. Узлы находятся один раз: `child`/`next`/`txt`.
  3. Все привязки блока — в одном `renderEffect`; `setText`/`setClassName` помнят прошлое значение.
  4. `v-for` и `v-if` — свои эффекты и блоки (`createFor`, `createIf`).

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Шаблон минифицирован: без кавычек и хвостовых тегов, `<!>` — якорь `v-if` → «раздел Два вывода».
- Лишние записи в DOM отсекает память узла (`$txt`, маска класса), а не отдельный эффект на узел → «раздел Рантайм».
- Строка списка с тем же ключом получает новое значение в ячейку, будится только её эффект → «раздел Списки и условия».
- Смешивание режимов только через `vaporInteropPlugin` → «раздел Включение».
- Нет Options API, `getCurrentInstance()`, `globalProperties` → «раздел Чего нет в rc.9».
- Вес выигрывается, только если всё дерево на `createVaporApp` → «раздел Вес».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Эффект один на блок, а не на узел; меньше DOM — только на `v-if` и очистке списка.
- VDOM-компонент в `createVaporApp` без плагина — пустота, в prod без единого слова.
- Один Vapor-компонент в VDOM-приложении утяжеляет сборку; вывод компилятора RC — не API.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>
