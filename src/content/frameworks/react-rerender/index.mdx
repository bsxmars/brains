  ### Bailout — пропуск компонента: три условия, все обязательны

  <Card tone="info" color="tone" pad={16} radius={4} gap={9} size={15.5} lh={1.6} text={PLAIN_BAILOUT} />

  <Card title="Что React проверяет в начале `beginWork` — обработки фибера" titleSize={17} pad={20} gap={14}>
    <CodeBlock code={BAILOUT_CODE} />

    <NumberedList
      items={[
        '`oldProps === newProps` — не поверхностное сравнение, а **сравнение ссылок на объект пропсов целиком**. Тот же самый объект, а не эквивалентный.',
        'Контекст, на который подписан компонент, не менялся.',
        'У самого фибера нет запланированной работы нужного приоритета (в текущих полосах) — то есть на нём не звали `setState`.',
      ]}
      size={15.5}
    />


    Внутри `bailoutOnAlreadyFinishedWork` есть вторая проверка, покрупнее. Если в
    `childLanes` нет работы текущего приоритета, функция возвращает `null`, и **React
    пропускает всё поддерево** — за одно сравнение чисел. Отметки в `childLanes` ставит сам
    `setState`: он поднимается от своего фибера к корню и помечает каждого предка.

    <CardNote tone="warn">

      Первое условие само по себе почти никогда не выполняется: родитель на каждом рендере
      заново вычисляет JSX, и каждый раз получается **новый объект `props`**. `React.memo`
      меняет именно эту проверку: сравнивает не объект целиком, а каждый проп по отдельности
      через `Object.is`. Это и называют поверхностным сравнением.

    </CardNote>
  </Card>

  ### Приём, о котором знают меньше: `children` как проп

  <Card title="Пропуск компонента без `memo` и без затрат" titleSize={17} pad={20} gap={13}>
    <CodeBlock code={CHILDREN_TRICK} />


    В `Good` элемент `<Slow />` создаётся в `Good`, а не в `Wrapper`. Когда `Wrapper`
    перерисовывается из-за своего `setN`, `Good` заново не вызывается — значит объект
    элемента **тот же самый**: он проходит через `props.children` без изменений. React
    доходит до фибера `Slow` и видит, что `oldProps === newProps` буквально, а работы на
    фибере нет. Это bailout: функция `Slow` не вызывается.

    <CardNote tone="ok">

      В демо это четвёртая и пятая строки таблицы: состояние в `Content`, `Article` внутри —
      вызван; `Article` через `children` из `App` — ноль вызовов, **без всякого `memo`**.
      Так вручную получается то, что Vue делает по умолчанию для слотов со статическим
      содержимым.

    </CardNote>
  </Card>

  ### Контекст идёт мимо `memo`

  Как провайдер находит читателей в обход `memo`, собрано своими руками в [«React изнутри: хуки и контекст», раздел «Контекст»](/frameworks/react-hooks-internals/#s5).

  <DarkPanel eyebrow="Смена значения провайдера: две последние строки таблицы">
    <CardGrid min={260} gap={14}>
      <DarkCard title="memo выкл" titleTone="warn" foot="смена значения провайдера">

        Перерисовалось **всё дерево** — семь вызовов из семи.

      </DarkCard>
      <DarkCard title="memo вкл" titleTone="info" foot="то же самое действие">

        Вызваны **двое**: `App` и `ThemeLabel`. Промежуточный `Content` — ноль.

      </DarkCard>
    </CardGrid>

    <DarkText>

      Подписка на контекст — отдельный механизм. Когда значение провайдера меняется, React
      проходит по поддереву и помечает работой каждый компонент, который читает этот
      контекст, — потребителя. Пометка ставится мимо проверки пропсов, поэтому `memo` здесь
      бессилен. Но компоненты **между** провайдером и потребителем всё равно могут быть
      пропущены. React пройдёт через них вниз, потому что их `childLanes` не пуст, но их
      функции не вызовет. Обход будет, вызовов — нет. Дёшево, но не бесплатно.

    </DarkText>
  </DarkPanel>

  <Card tone="err" color="tone" pad="15px 17px" radius={4} size={16} lh={1.6}>

    Практическое следствие: **любое изменение значения провайдера перерисовывает всех
    потребителей**, какое бы поле они ни читали. React сравнивает значение целиком через
    `Object.is`. Положили в один провайдер `{ user, theme, cart }` — изменение корзины
    перерисует всех, кто читает тему. Рабочие приёмы: разделить контексты по тому, как
    часто они меняются; держать состояние и функцию его изменения (`dispatch`) в разных
    контекстах; обернуть значение провайдера в `useMemo`.

  </Card>

  ### Компонент, объявленный внутри компонента

  <Card tone="err" title="Самая дорогая опечатка в React" titleSize={17} pad={20} gap={13}>
    <CodeBlock code={NESTED_COMPONENT} />


    При каждом вызове `Parent` создаётся новая функция `Row`, значит `oldType === newType`
    ложно. Компоненты разных типов React не сопоставляет: старый фибер помечается на удаление
    (`Deletion`), новый — на вставку (`Placement`). Всё поддерево сносится: теряются
    состояние, фокус и позиция прокрутки, все эффекты запускаются заново. Симптом обычно
    описывают как «инпут теряет фокус при вводе».

    <CardNote tone="ok">

      На React 19.3 — два монтирования на каждый ре-рендер родителя. Если объявить `Row`
      на верхнем уровне модуля — ноль. Так и лечится.

    </CardNote>
  </Card>

  ### Первый рендер: всё, что выше, ещё не работает

  равен `null` — сравнивать не с чем, и React идёт вниз по всему дереву без единой развилки.

    `TaskRow` **не размонтировался** — значит его `useState`, его `useRef`, текст
    в неуправляемом `input` (его значение хранит браузер, а не React) и позиция прокрутки

    Наблюдаемый симптом ровно такой: **данные съехали на одну позицию, а всё остальное
    осталось на месте.** Это не «React всё перемонтировал» — как раз наоборот, он ничего
    не перемонтировал, и в этом проблема: он переиспользовал фиберы для не тех сущностей.

    <CardNote tone="warn">

      Номер фибера в демо выдаётся один раз при монтировании и доказывает переиспользование:
      после удаления первой строки «Задача B» стоит на фибере `#1`.

    </CardNote>
  </Card>

  <CardGrid min={280} gap={14}>
    <Card tone="warn" color="tone" pad={16} radius={4} size={15.5}>

      **Когда `key={index}` безопасен.** Когда список не переупорядочивается и не удаляется

      состояния. Условия выполнимые, но хрупкие: любая будущая сортировка ломает всё тихо,

    </Card>
    <Card pad={16} radius={4} size={15.5}>

      **Ключ уникален среди соседей, а не глобально.** Два элемента с `key="1"` в разных
      списках — норма. А `Math.random()` в ключе сносит элемент на каждом рендере: новый
      ключ означает новую сущность.

    </Card>
    <Card tone="info" pad={16} radius={4} size={15.5}>

      **Vue устроен здесь идентично.** Тот же смысл `key` в `v-for` и на компоненте, тот же

  </Card>

    В документации React прямо сказано: React вправе выбросить закэшированное значение
    и пересчитать. Значит `useMemo` не годится, чтобы что-то случилось ровно один раз.
    Классическая ошибка — `const socket = useMemo(() => new WebSocket(url), [url])`.
    Что сокет создастся один раз, никто не обещает, но важнее другое: **создание сокета —
    побочный эффект в render-фазе**. Сокет откроется, даже если рендер выбросят, и `close()` никто
    не вызовет. Правильное место — `useEffect` с cleanup.

  </Card>

    пропуск дочернему поддереву — как в приёме с `children`.

    <CardNote tone="warn">

      поручиться**, — молча пропускает его. Отсюда порядок действий: сначала линтер и починка нарушений,

      с документацией компилятора.

    </CardNote>
