# Индексы Postgres и EXPLAIN

`data/indexes` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** B-дерево — отсортированные значения с адресами строк; `EXPLAIN` — выбранный план.
- **Зачем:** запрос читает страницы по 8 КБ; индекс экономит их, когда строк мало и они кучно.
- **Как работает:** планировщик считает цену Seq, Index и Bitmap Scan по статистике (число строк, `correlation`) и берёт дешёвый. `Seq Scan` — индекс не подходит, правда дороже или оценка строк ошиблась. Проверка — `EXPLAIN (ANALYZE, BUFFERS)`: оценка против факта, страницы.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Поиск — по странице на уровень; рост — делением страниц → «раздел B-дерево».
- `rows` — за проход, `Buffers` — за все → «раздел Как читать EXPLAIN».
- Порядок строк важнее доли; на рассыпанных выигрывает Bitmap → «раздел Выбор плана».
- Индекс ломают функция над столбцом, чужой тип, `LIKE '%…'`, не ведущий столбец → «раздел Почему индекс не берётся».
- Старая статистика — вложенный цикл вместо хеша → «раздел Почему индекс не берётся».
- Index Only Scan, `INCLUDE`, частичные индексы → «раздел Index Only Scan и особые индексы».
- Каждый индекс удорожает `INSERT` → «раздел Цена на запись».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `actual rows=2 loops=9000` — это 18 000 строк.
- `EXPLAIN ANALYZE` выполняет запрос: изменяющие — в `BEGIN … ROLLBACK`.
- 1 % строк бывает на всех страницах.

</details>
