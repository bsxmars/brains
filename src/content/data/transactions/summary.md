# Транзакции и уровни изоляции

`data/transactions` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** транзакция — «всё или ничего»; уровень изоляции решает, какие чужие изменения она видит и какие аномалии разрешены.
- **Зачем:** чтобы читатели не ждали писателей, Postgres хранит версии строк и даёт каждой транзакции свой снимок.
- **Как работает:** `UPDATE` пишет новую версию с `xmin`/`xmax`; видимость — по снимку и статусу транзакций. Read Committed: снимок на оператор, при конфликте пишет поверх свежей версии. Repeatable Read и Serializable: один снимок, при конфликте `40001`.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- C — только объявленные правила, I — уровнями → «раздел Что обещает транзакция».
- Откат ничего не стирает; номер транзакции — при первой записи → «раздел Версии строк».
- Грязного чтения нет нигде; Repeatable Read без фантомов → «раздел Снимки и уровни».
- Потерянное обновление, фантом, write skew по шагам → «раздел Аномалии по шагам».
- `x = x + 1` безопасен на Read Committed, «прочитать — посчитать — записать» — нет → «раздел Конфликт записи».
- Режимы `FOR …`, внешние ключи, оптимистичная блокировка → «раздел Блокировки строк».
- Write skew ловит только SSI → «раздел Serializable».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Снимок берётся первым запросом, не `BEGIN`.
- Повторять всю транзакцию, эффекты — после `COMMIT`; `UPDATE 0` — тоже конфликт.
- `FOR UPDATE` на родителе блокирует вставку детей — нужен `FOR NO KEY UPDATE`.

</details>

<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Снимок — `xmin:xmax:xip` → «раздел Версии строк».
- Повторять только `40001` и `40P01`; `25P02` — транзакция сломана → «раздел Повтор и дедлоки».

- `READ ONLY DEFERRABLE` — отчёт без `40001` → «раздел Serializable».
- `xmax` у живой версии — след блокировки → «раздел Тонкие места».

</details>
