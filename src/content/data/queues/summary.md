# Очереди и идемпотентность

- Подтверждение сообщения и изменение базы — разные операции. Сбой между ними приводит к повторной обработке или потере эффекта в зависимости от порядка действий.
- Обработчик должен узнавать повтор по устойчивому id события. Записывайте этот id и результат в одной транзакции: повтор не должен начислить деньги или изменить состояние ещё раз.
- Подтверждайте сообщение после успешного эффекта. Таймаут обработки и повторная выдача допускают одновременную работу нескольких обработчиков, поэтому одна аренда не заменяет идемпотентность.
- Outbox записывает событие вместе с бизнес-изменением в одной базе. Ретранслятор публикует его отдельно и может отправить повторно; потребитель всё равно должен различать дубли.
- Порядок доставки нельзя подменять номером последнего увиденного сообщения. Отбрасывание старой версии подходит полному состоянию, но может потерять необходимую дельту.
- Ограничьте повторы, отделите неисправимые сообщения и обеспечьте наблюдаемость. Письмо, платёж или вызов чужого API требуют собственной защиты от повторного эффекта.
