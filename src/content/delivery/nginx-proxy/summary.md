# Nginx как обратный прокси

`delivery/nginx-proxy` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** сервер перед приложением, который принимает запросы вместо него и решает, кто их обслужит и что увидит бэкенд.
- **Зачем:** раздавать статику, держать TLS, делить адреса между сервисами и кешировать ответы.
- **Как работает:** порт и `Host` выбирают `server` → внутри ровно одна `location` по алгоритму в пять шагов → `proxy_pass` пересылает путь как есть или с заменой совпавшей части → ответ буферизуется.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Имя не подошло — отвечает `default_server`, а без него первый по порядку; звёздочка закрывает любое число меток → «раздел Какой server ответит».
- `=` → самый длинный префикс → `^~` → регулярки сверху вниз → префикс → «раздел Какая location ответит».
- Без URI в `proxy_pass` путь сырой, с URI — нормализованный и с заменой; у регулярки URI запрещён → «раздел proxy_pass: слеш и путь».
- Бэкенд не знает `Host`, адрес клиента и HTTPS, пока их не передали; `proxy_set_header` наследуется «всё или ничего» → «раздел Заголовки к бэкенду».
- Буферизация может склеить SSE в пачку; 502 — не достучались, 504 — не успел → «раздел Буферизация и таймауты».
- `try_files … /index.html` для маршрутов SPA, но не для ассетов и API → «раздел SPA и try_files».
- `proxy_cache`, `$upstream_cache_status`, `use_stale`, `proxy_cache_lock`, gzip → «раздел Кеш и gzip».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Регулярка перебивает более длинный префикс; регулярки выбираются по порядку, а не по точности.
- Слеш в `proxy_pass`: `/v2` + `http://backend/` даёт `//users`, а `location /v2` ловит и `/v2beta`.
- `try_files` отвечает 200 с HTML на пропавший старый бандл; первый адрес в `X-Forwarded-For` пишет клиент.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `return 444` — закрыть без ответа → «раздел Какой server ответит».
- Автоматический 301 со слешем уводит на внутренний порт; лечит `absolute_redirect off` → «раздел proxy_pass: слеш и путь».
- С 1.29.7 к бэкенду HTTP/1.1 по умолчанию, раньше 1.0 с `Connection: close` → «раздел Заголовки к бэкенду».
- `X-Accel-Buffering: no` или `proxy_buffering off`; `proxy_read_timeout` 60 с → «раздел Буферизация и таймауты».
- Ответ с `Set-Cookie` не кешируется; ключ кеша — адрес бэкенда → «раздел Кеш и gzip».
- `gzip_types` по умолчанию только HTML, `gzip_proxied off` не сжимает для CDN → «раздел Кеш и gzip».

</details>
