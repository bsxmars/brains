# DNS: от имени до адреса

`delivery/dns` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** цепочка серверов, каждый знает только свою зону и ссылку на следующего; ответ оседает в кешах на срок TTL.
- **Зачем:** соединяются с IP-адресом, а не с именем — до первого запроса кто-то должен превратить имя в адрес.
- **Как работает:** stub-резолвер ОС шлёт вопрос с RD рекурсивному резолверу → тот спускается от корня по делегированиям NS (с glue) до авторитетного сервера → CNAME в чужую зону запускает новый спуск → всё по дороге ложится в кеш со своим TTL, включая отказы.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Авторитетный отвечает из первых рук (флаг AA), резолвер пересказывает → «раздел Путь запроса».
- Пакет: заголовок, вопрос, три секции записей, сжатие имён указателями → «раздел Пакет».
- Кешей три-четыре (браузер, ОС, резолвер), каждый отдаёт остаток срока; отказ тоже кешируется → «раздел TTL и кеш».
- CNAME не терпит соседей, поэтому на вершине зоны нельзя; обходы — ALIAS, flattening, A, редирект → «раздел CNAME и apex».
- Смена адреса — постепенный переезд; DNS-балансировка не знает о здоровье → «раздел Выкатка».
- Запись HTTPS, DoH, `dns.lookup` против `dns.Resolver` → «раздел Браузер и Node».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- TTL понижают заранее, за старый TTL: новый срок узнают только спросившие после правки.
- TTL не ограничивает соединения: keep-alive, HTTP/2, WebSocket держат старый адрес — старый сервер гасят по журналу, а не по часам.
- Проверили имя до создания записи — NXDOMAIN закеширован на `minimum` из SOA.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Заголовок 12 байт; указатель от `0xC0`; UDP 512 байт, иначе `TC` и TCP; EDNS(0) около 1232 → «раздел Пакет».
- Срок отказа — меньшее из TTL SOA и `minimum` (RFC 2308) → «раздел TTL и кеш».
- Один ответ резолвера стенда — семь запросов к четырём серверам → «раздел Путь запроса».
- NXDOMAIN (`ENOTFOUND`) против NODATA (`ENODATA`) → «раздел Тонкие места».
- `dns.lookup` — `getaddrinfo` в пуле libuv из четырёх потоков; ни он, ни `Resolver` не кешируют → «раздел Браузер и Node».
- HTTPS — тип 65 (RFC 9460), сообщает `alpn` до соединения → «раздел Браузер и Node».

</details>
