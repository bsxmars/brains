# Фича-флаги: раскатка без деплоя

`delivery/feature-flags` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** условие в коде, чьё значение приходит из отдельной настройки; по сути чистая функция: контекст на входе, вариант на выходе.
- **Зачем:** менять поведение уже выкаченного кода у части пользователей за секунды, без сборки, и выключать в аварию быстрее отката.
- **Как работает:** выключен — значение вызывающего → правила по очереди, решает первое совпавшее → иначе доля: хеш от «ключ флага + `targetingKey`» даёт корзину, доля — порог → иначе вариант по умолчанию.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Значение по умолчанию передаёт вызывающий код при каждом вызове → «раздел Флаг — функция».
- Рост доли только добавляет людей; липкость держит тройка «ключ, порядок вариантов, формула» → «раздел Корзины и хеш».
- OpenFeature: один API, провайдер под конкретный сервис, хуки, подробный ответ; контекст слоями, ближний побеждает → «раздел OpenFeature».
- Сервер, браузер или edge: меняется момент готовности и кто видит правила; клиент мигает → «раздел Где вычислять».
- Выключатель проверяют заранее; удаляют сначала код, потом флаг → «раздел Выключатель и долг».
- Канарейка делит версии, флаг — ветки внутри версии; дополняют друг друга → «раздел Флаг или канарейка».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Переименование флага, перестановка вариантов или три варианта перемешивают пользователей.
- Пользователь в глобальном контексте сервера — соседний запрос получит чужой вариант.
- Default `true` или удаление флага раньше кода — функция включится или пропадёт у всех при аварии.

</details>
