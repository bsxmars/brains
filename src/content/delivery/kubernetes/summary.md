# Kubernetes: развёртывание

- Kubernetes поддерживает желаемое состояние через контроллеры, которые снова и снова сравнивают его с фактическим. Принятый API-объект ещё не означает готовую работающую систему.
- Deployment управляет версиями через ReplicaSet, а Pod представляет единицу запуска. Замена Pod создаёт новый экземпляр, поэтому временное локальное состояние может исчезнуть.
- Scheduler выбирает узел с учётом requests и ограничений размещения. Limits и доступные ресурсы влияют на выполнение уже запущенного контейнера отдельно.
- Readiness определяет готовность принимать обычный трафик, liveness — необходимость перезапуска, startup даёт время на запуск. Неподходящая проба способна ухудшить аварию.
- Service и EndpointSlice связывают клиентов с экземплярами; обновление адресов и завершение соединений не мгновенны. Для выката нужны корректная готовность, обработка остановки и совместимость соседних версий.
