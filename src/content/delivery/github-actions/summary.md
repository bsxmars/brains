# GitHub Actions: конвейер

- Workflow описывает запуск по событию, jobs и шаги. Сначала формируется граф работы, затем runner выполняет подготовленные задания.
- Job и шаг имеют разные границы: шаг обычно запускает новый процесс оболочки, а отдельный GitHub-hosted job получает новое окружение. Self-hosted runner может сохранять состояние диска.
- Значения передают через предусмотренные outputs и env-механизмы, файлы между jobs — артефактами. Кеш ускоряет повторную работу, но не заменяет надёжную передачу результата сборки.
- Код из pull request и выражения из внешнего ввода могут быть недоверенными. Ограничивайте permissions, доступ к секретам и полномочия постоянного runner.
- Связывайте деплой с проверенным артефактом и управляйте конкурентными выкладками. Успех одного шага не означает, что весь workflow или публикация уже завершены.
