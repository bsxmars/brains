# TLS и сертификаты

- TLS защищает соединение, а проверка сертификата связывает сервер с нужным именем. Шифрование без проверки подлинности может защищать разговор с атакующим.
- Клиент проверяет цепочку до доверенного корня, срок действия и имя в SAN. Отправленный сервером корневой сертификат сам по себе не делает его доверенным.
- Во время рукопожатия стороны согласуют параметры и получают ключи; сервер подтверждает владение закрытым ключом. Сертификат и закрытый ключ выполняют разные роли.
- SNI помогает выбрать сертификат, ALPN — протокол приложения. Имя для TLS, HTTP Host и адрес подключения могут различаться, поэтому проверяйте их согласованность.
- Выпуск, обновление и загрузка нового сертификата — разные шаги эксплуатации. Следите за сроками, полной цепочкой и доступом к ключу; отключение проверки сертификата не является исправлением доверия.
