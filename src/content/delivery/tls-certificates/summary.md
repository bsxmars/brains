# TLS и сертификаты

`delivery/tls-certificates` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** протокол поверх TCP, который шифрует соединение и доказывает, что на том конце владелец имени из адреса.
- **Зачем:** без проверки сертификата шифрование защищает разговор с кем угодно; почти все поломки HTTPS — во второй половине: цепочка, срок, имя.
- **Как работает:** ClientHello с SNI, ALPN и сразу частью ключа → ServerHello, и дальше всё шифруется → сервер присылает цепочку и подписывает рукопожатие (CertificateVerify) → клиент проверяет цепочку до доверенного корня, срок и имя в SAN; всё за один круг.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Сообщения рукопожатия, гибридный `X25519MLKEM768`, SNI выбирает сертификат, keylog → «раздел Рукопожатие».
- Билет переносит доверие; 0-RTT можно повторить — только идемпотентное → «раздел Возобновление и 0-RTT».
- Промежуточный отдаёт сервер; Chromium достраивает по AIA, Node — нет → «раздел Цепочка доверия».
- Имя сверяют с SAN, звёздочка — ровно одна метка, срок — по часам клиента → «раздел Имя и срок».
- ACME: аккаунт, заказ, вызов (`http-01`, `dns-01`, `tls-alpn-01`), CSR, сертификат; ARI подсказывает, когда продлевать → «раздел ACME».
- OCSP уходит, вместо отзыва — короткие сроки; HSTS и preload; mTLS → «раздел Отзыв, HSTS, mTLS».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Без промежуточного «в браузере работает», а Node и curl падают — проверять `openssl s_client`.
- Node называет последнюю найденную ошибку, Chromium — самую важную: починили одну, ждите следующую.
- `rejectUnauthorized: false` выключает всё; Node принимает имя из CN, браузеры — только SAN.

</details>
