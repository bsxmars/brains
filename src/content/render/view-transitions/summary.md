# View Transitions: анимация между состояниями

`render/view-transitions` · выжимка обновлена 2026-11-12. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** API анимирует снимки старого и нового состояний, а DOM изменяет ваш колбэк.
- **Последовательность:** старый снимок → колбэк → updateCallbackDone → новый снимок и ready → анимация → finished.
- **Пропуск:** skipTransition убирает анимацию, но не откатывает изменение DOM; колбэк обновления всё равно должен выполниться.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Три промиса и их разные отказы → «Два снимка, колбэк и три промиса».
- Имя связывает снимки элементов, но должно быть уникальным в каждом состоянии → «Имена».
- Асинхронный колбэк удерживает отрисовку; фреймворк должен завершить обновление до нового снимка → «Место в кадре».
- Новый переход поверх старого, ошибки и пропуск → «Прерывание».
- @view-transition, pageswap, pagereveal и предрендер → «Между документами».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Дубль имени отклоняет ready, но не отменяет выполненное обновление.
- Обработайте отказ ready: быстрое повторное действие может пропустить предыдущую анимацию.
- Не рассчитывайте, что API самостоятельно учтёт prefers-reduced-motion.

</details>
