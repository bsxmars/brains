# Кадр браузера

`render/render-pipeline` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** порядок шагов между двумя vsync: задача, микрозадачи, rAF, наблюдатели, style, layout, pre-paint, paint, commit; дальше — без главного потока.
- **Зачем:** DOM однопоточен, JS и рендер делят одни миллисекунды; граница commit объясняет, почему `transform` плавный, а `left` дёргается.
- **Как работает:** на vsync браузер решает, нужен ли кадр; пока не кончились задача и все микрозадачи, кадра нет; paint строит display list; после commit композитор сам растрирует плитки и собирает кадр.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- `rAF` видит геометрию прошлого кадра, `ResizeObserver` — новую, `MutationObserver` — микрозадача до кадра → «раздел Кадр по шагам».
- Кадра может не быть; поток браузеру отдают задачей, не микрозадачей → «раздел Кадра может не быть».
- Дорого чередование чтения и записи геометрии; сужают пересчёт `contain`, `content-visibility` → «раздел Чтение и запись».
- Без главного потока — только объявленная анимация `transform`/`opacity`; слой стоит видеопамяти; `will-change` меняет вёрстку → «раздел Что дешевле двигать».
- Vue обновляет в микрозадаче, React частично в задачах → «раздел Где живёт фреймворк».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Одно некомпозитное свойство в keyframes уводит на главный поток всю анимацию.
- `innerText` форсирует раскладку, `textContent` — нет.
- Слушатель `wheel`/`touchmove` без `passive` возвращает прокрутку на главный поток.

</details>
