# Стили веб-компонентов: Shadow DOM и каскад

`render/web-components-styles` · выжимка обновлена 2026-11-12. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** Shadow DOM ограничивает область обычных селекторов, сохраняя наследование и пользовательские свойства.
- **Настройка:** страница выбирает хост, передаёт переменные и использует явно открытые part; внутренний CSS сам решает, где их применить.
- **Каскад на границе:** у обычных объявлений сильнее внешний контекст, у important — внутренний; это сравнение происходит раньше специфичности.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Сквозная карточка и работающая проверка границы → «Граница».
- :host настраивает элемент-хост из корня → «:host».
- ::slotted выбирает непосредственно назначенные элементы, а не произвольных потомков → «::slotted».
- part и exportparts открывают именованные внутренние элементы → «::part».
- Общий CSSStyleSheet, декларативный корень, поздняя регистрация → «Общие листы» и «Декларативный корень».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Светлый DOM не становится теневым после назначения в slot: селекторы страницы продолжают его находить.
- Сброс all не отменяет пользовательские свойства; шрифты и контролы требуют явного решения.
- Повторный attachShadow при гидратации может удалить серверное содержимое: проверяйте существующий корень.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Пары правил и таблицы сброса сохранены в раскрываемых подробностях.
- Поддержка :host-context, @font-face и краевые случаи указаны для конкретных версий стенда.
- Изоляция CSS не означает защиту секретов и не заменяет модель доверия страницы.

</details>
