# WebGL и конвейер GPU

`render/webgl` · выжимка обновлена 2026-11-12. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** GPU рисует содержимое canvas по вашим данным и шейдерам; браузер размещает сам canvas через обычный CSS.
- **Конвейер:** вершины → вершинный шейдер → растеризация → фрагментный шейдер → глубина/смешивание → цветовой буфер.
- **Обязанности приложения:** сцена, попадание указателя, доступность и восстановление ресурсов не возникают автоматически из пикселей.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Две дороги от DOM и команд WebGL к композитору → «Где кончается браузер».
- Шейдеры, прозрачность, глубина, мипмапы и framebuffer → «Конвейер».
- Количество вызовов, смен состояния и фрагментов определяет разные части цены → «Что здесь стоит дорого».
- drawArrays отправляет команду, а не подтверждает завершение GPU → «Почему время здесь мерить трудно».
- После потери контекста ресурсы нужно создать заново → «Потеря контекста».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- В диагностике 0:10 второе число — строка, первое — номер исходника. WebGL shaderSource принимает одну строку, а не массив OpenGL.
- Фрагмент не равен экранному пикселю: фигуры перекрываются, часть фрагментов может быть отброшена.
- rAF вашей страницы выполняется на главном потоке; отдельный GPU не переносит туда ваш JS.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Инстансинг рисует много копий одной геометрии; батч объединяет геометрию. Сравнение демо считает вызовы и байты.
- GPU timer query читают позже и проверяют disjoint; секундомер вокруг draw меряет отправку.
- Подробные примеры глубины, прозрачности и двух проходов доступны в раскрываемых блоках.

</details>
