# WebGPU: другая модель работы с видеокартой

`render/webgpu` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** модель Vulkan/Metal/D3D12 в браузере: явные объекты вместо глобального состояния WebGL, плюс вычисления без рисования.
- **Зачем:** WebGL перепроверяет всё состояние на каждом вызове; WebGPU проверяет один раз при создании объектов — цена переносится из кадра в подготовку.
- **Как работает:** адаптер → устройство → очередь; неизменяемый конвейер и группы привязок создаются заранее; команды пишутся в энкодер, `finish()` → `queue.submit` пачкой; результат читается отдельно через `mapAsync`.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- `requestAdapter()` может вернуть `null`; адаптер бывает программным; пределы устройства — базовые, не адаптера → «раздел Другая модель».
- Командный буфер одноразовый, конвейер не правится; раскладка против шейдера, группа против раскладки → «раздел Запись и отправка».
- Сетка рабочих групп, память группы, барьер; гонка без атомиков и локальная гистограмма → «раздел Вычисления».
- Читать можно только через промежуточный буфер; после `unmap()` данных нет → «раздел Чтение результата».
- Ошибки не бросаются: объект «недействителен», ловят областями ошибок; `device.lost` → «раздел Ошибки».
- Проверять адаптер, а не `navigator.gpu`; когда что брать → «раздел Поддержка и выбор».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Забытый флаг `STORAGE`: ни одного исключения, цепочка недействительных объектов, на выходе нули.
- Выход за край массива в шейдере не падает — тихо читает чужие данные.
- Барьер после раннего `return`: Firefox собирает молча, Chromium и WebKit — нет.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Адаптер 1024 вызова в группе, устройство по умолчанию 256; больше — `requiredLimits` → «раздел Другая модель».
- Не больше 65 535 групп на измерение; групп с запасом: `ceil(n / 64)` → «раздел Вычисления».
- `MAP_READ` сочетается только с `COPY_DST`; `mapState`: `unmapped` → `pending` → `mapped` → `unmapped` → «раздел Чтение результата».
- Порядок `onSubmittedWorkDone` и `mapAsync` не обещан → «раздел Чтение результата».
- Адаптер Chromium после `requestDevice` «израсходован» — восстанавливать с нового → «раздел Ошибки».

</details>
