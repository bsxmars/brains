# Критический путь и Web Vitals

`render/rendering-crp` · выжимка обновлена 2026-11-12. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** LCP отмечает появление крупного содержимого, INP — задержку ответа на взаимодействие, CLS — неожиданные сдвиги.
- **Причина:** браузер ждёт не только байты. Для показа нужны готовые стили и время потока на раскладку и рисование; быстрая загрузка изображения сама не гарантирует быстрый LCP.
- **Диагностика:** сначала найти длинную часть ожидания, затем менять её причину.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Разбор HTML, блокирующий CSS, sync/async/defer и preload scanner → «Критический путь».
- LCP изображения: TTFB, задержка запроса, загрузка и задержка показа → «LCP».
- CLS = impact × distance, затем худшее окно серии сдвигов → «CLS».
- INP: input delay, processing и presentation; микрозадача не освобождает кадр → «INP».
- Обычный Lighthouse navigation использует TBT; timespan может измерить INP по взаимодействиям → «Чем это мерить».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Последняя запись LCP и buffered:true нужны, чтобы не потерять уже случившегося кандидата.
- С Chrome 133 округлённый renderTime доступен и у cross-origin изображений без Timing-Allow-Origin; startTime уже выбирает время показа или запасное loadTime.
- Зелёный TBT одного прогона не гарантирует хороший INP у пользователей.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Пороги CWV — политика Google; полевой p75 и один лабораторный сценарий отвечают на разные вопросы.
- Сдвиги вскоре после учитываемого ввода исключаются; зарезервированное место предотвращает поздний сдвиг.
- Long Tasks описывает отдельную задачу, LoAF — длительное обновление кадра.

</details>
