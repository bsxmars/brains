# Безопасность фронтенда

<details>
<summary><b>Ядро</b> — отправка, чтение и исполнение имеют разные границы</summary>

- SOP ограничивает чтение чужих данных. CORS позволяет серверу открыть ответ конкретному origin; отказ CORS не откатывает уже обработанный запрос.
- CSP ограничивает загрузку и исполнение кода. Nonce с `strict-dynamic` задаёт вход доверия и разрешает динамическую загрузку из уже работающего скрипта.
- CSRF использует автоматически выбранные браузером куки. Сервер проверяет намерение через токен, Origin и Fetch Metadata; SameSite уменьшает число подходящих межсайтовых запросов.
- HttpOnly скрывает значение куки от JS API. Внедрённый код всё ещё может делать запросы от имени пользователя и читать доступные ответы.

</details>

<details>
<summary><b>Подвох</b> — разрешение одной операции не разрешает остальные</summary>

- Успешный статус 200 не гарантирует чтение через fetch. Простой запрос может уйти без preflight, даже когда ответ будет скрыт CORS.
- `Allow-Headers: *` не заменяет явный request Authorization. Response Authorization открывается `Expose-Headers: *` без credentials; при include нужен явный список. Set-Cookie остаётся скрытым.
- Декодер JWT не проверяет подпись. Для HS256 секрет остаётся на сервере; асимметричную подпись можно проверить публичным ключом, но серверная авторизация всё равно обязательна.
- navigator.locks сериализует работу. Один общий результат во всех вкладках требует ещё и обмена токеном или отдельного координатора.

</details>

<details>
<summary><b>Детали</b> — условия примеров и измерений</summary>

- Запись DevTools `(blocked:csp)` не доказывает отправку по сети: запрещённая картинка может получить такую запись без обращения к серверу.
- `null` — сериализация opaque origin. Независимые opaque origin различны; одна и та же идентичность равна себе. Правила file: зависят от реализации.
- HttpOnly-cookie нельзя надёжно проверить или удалить через document.cookie. Ошибка запроса не сообщает фронту, почему браузер не приложил куку.
- Цифры точности часов и поведения изоляции — снимок указанной версии Chromium. Живое демо отдельно спрашивает текущий контекст читателя.
- CSP и Trusted Types подробнее разобраны в [отдельной теме](/platform/csp/), каналы наблюдения без чтения — в [XS-Leaks](/platform/xs-leaks/).

</details>
