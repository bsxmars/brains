# Безопасность фронтенда

`platform/security` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** механизмы браузера и сервера для среды, где на одной странице работает код десятков недоверяющих сторон с общими куками пользователя.
- **Зачем:** из этой среды растут три проблемы — чужой сайт читает ваши ответы, чужой код исполняется у вас (XSS), чужой сайт действует от имени пользователя (CSRF).
- **Как работает:**
  - SOP — политика чтения, не отправки; CORS — разрешение сервера читать его ответ.
  - CSP — второй рубеж против XSS: nonce + `'strict-dynamic'` вместо списка доменов.
  - Против CSRF — `SameSite`, `Sec-Fetch-Site`/`Origin` и токен; против кликджекинга — `frame-ancestors`.
  - `HttpOnly` защищает от кражи токена, а не от XSS.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Origin — протокол + хост + порт; site — регистрируемый домен; куки живут не в origin-модели → «раздел Origin и правило одного источника».
- Простой запрос выводится из того, что умела форма; разрешение проверяется дважды — на preflight и на ответе → «раздел CORS и preflight».
- `default-src` не покрывает `frame-ancestors`, `base-uri`, `form-action`; внедрять через report-only → «раздел CSP».
- XSS через `innerHTML` без `<script>`, схема `javascript:` в `href`, mXSS, Trusted Types → «раздел XSS».
- Таблица `SameSite`: `Strict`, `Lax`, `None`; Fetch Metadata → «раздел CSRF и кликджекинг».
- Нагрузка JWT читается кем угодно; access в памяти + refresh в `__Secure-`-куке с `Path` эндпоинта; гонка обновления и `navigator.locks` → «раздел Куки и JWT для фронта».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Отражение `Origin` с `Allow-Credentials: true`, `Origin: null` в белом списке, `HasSuffix` — отдают данные всему интернету; только точный список.
- `POST` с `text/plain` и JSON внутри — простой запрос без preflight: CSRF в «JSON-API».
- Забытый `Vary: Origin` отравляет кеш CDN; `frame-ancestors` не работает в `<meta>`.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Около 95% политик со списком доменов обходились (ACM CCS 2016) → «раздел CSP».
- Без `Expose-Headers` JS видит семь заголовков ответа; `Allow-Headers: *` не покрывает `Authorization` → «раздел CORS и preflight».
- Chromium: исключение «Lax + POST» две минуты и только для умолчательного `Lax` → «раздел CSRF и кликджекинг».
- `exp` в секундах, `Date.now()` — в миллисекундах; `atob` не понимает base64url → «раздел Куки и JWT для фронта».
- `__Host-`: `Secure`, `Path=/`, без `Domain` → «раздел Origin и правило одного источника».

</details>
