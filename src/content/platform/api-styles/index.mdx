  ### Трейлеры: почему браузеру нужен gRPC-web

  <Card tone="info" color="tone" pad={16} radius={4} gap={9} size={15.5} lh={1.6} text={PLAIN_TRAILERS} />

  Настоящий gRPC работает поверх HTTP/2. Тело ответа — сообщения в кадрах по 5 + N байт,
  а статус вызова (`grpc-status`) сервер присылает трейлерами: ещё одним кадром HEADERS
  после последнего кадра DATA. Статус в конце нужен потоковым вызовам: пока сервер шлёт
  сообщения, исход ещё неизвестен.
