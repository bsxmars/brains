# REST, GraphQL и gRPC-web

- Стиль API определяет, кто выбирает форму данных и как описываются операции. REST, GraphQL и gRPC-web переносят сложность в разные места, а не отменяют её.
- REST использует ресурсы и HTTP-семантику; составные представления могут уменьшить число запросов. Один ресурс не обязан соответствовать одной таблице базы.
- GraphQL позволяет запросить нужные поля, но исполнение резолверов может создать много обращений к источникам. Один HTTP-запрос не означает одну операцию базы или малую нагрузку.
- Схема и бинарное представление задают контракт gRPC-web, который отличается от обычного браузерного fetch JSON. Учитывайте прокси, типы сообщений и доступные виды потоковой передачи.
- Для любого стиля нужны авторизация, валидация, совместимость и понятные ошибки. Оценивайте полный сценарий экрана: сетевые ожидания, кеширование, объём ответа и работу сервера.
