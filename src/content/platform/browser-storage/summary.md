# Хранилища браузера

`platform/browser-storage` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** шесть мест для данных — куки, `localStorage`, `sessionStorage`, IndexedDB, Cache API, OPFS; все, кроме кук, принадлежат origin.
- **Зачем:** выбирают по правилам, а не по объёму: что можно положить, синхронно ли, кто видит, есть ли в воркере. Любое может оказаться пустым — источник правды сервер.
- **Как работает:**
  - `localStorage` синхронный, только строки — для пары значений, нужных сразу.
  - IndexedDB асинхронная, хранит объекты; транзакция фиксируется сама, когда неактивна и запросов нет.
  - Активна в своей задаче и её микрозадачах и в обработчиках запросов; ожидание новой задачи (`fetch`, таймер) её закрывает.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Куки читает сервер, остальные пять он не видит → «раздел Что где хранить».
- Событие `storage` приходит в другие вкладки того же origin; `sessionStorage` — своё у вкладки, копия при `window.open` → «раздел localStorage и sessionStorage».
- Схему меняют только в `onupgradeneeded`; старая вкладка без `close()` даёт `blocked` → «раздел IndexedDB».
- Необработанная ошибка запроса откатывает транзакцию целиком; `preventDefault()` спасает → «раздел Жизнь транзакции».
- Cache API: ключ — запрос целиком, срока годности нет; OPFS с синхронным доступом только в воркере → «раздел Cache API и OPFS».
- Вытеснение origin целиком, `persist()` — просьба, инкогнито стирает всё при закрытии → «раздел Квота и вытеснение».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `await fetch` внутри транзакции: следующий `put` бросает `TransactionInactiveError`, в базе половина. Сеть — до транзакции или между двумя.
- Но `await` запроса к базе и готового промиса безопасен.
- `setItem(key, obj)` молча пишет `"[object Object]"`; при переполнении `setItem` бросает — оборачивать в `try`.

</details>
