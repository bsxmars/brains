# Ограничение частоты в API

- Серверный ограничитель решает, принять ли запрос по выбранному ключу и бюджету. Лимит пользователя, IP, операции и всего сервиса — разные политики.
- 429 сообщает о превышении квоты, 503 — о временной невозможности обслуживания. Из статуса нельзя вывести точную причину или состояние всех экземпляров системы.
- Повтор допустим, когда операция безопасно повторяется, отказ может пройти и остался бюджет попыток. Для изменяющих действий нужен устойчивый способ не повторить эффект.
- Backoff уменьшает частоту, jitter разводит клиентов во времени, Retry-After задаёт минимальное ожидание. Немедленные повторы могут превратить частичный отказ в общую перегрузку.
- Ограничение частоты не заменяет предел параллелизма и общий бюджет повторов. Согласуйте ключ и счётчик между экземплярами, а forwarded-адрес доверяйте только известному прокси.
