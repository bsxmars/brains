# Ограничение частоты в API

`platform/rate-limits` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** HTTP вокруг лимита — каким кодом отказать, как сказать «когда вернуться», кого считать одним клиентом — и поведение клиента, который решает, повторять ли и когда.
- **Зачем:** лимит защищает сервер от того, кто шлёт слишком много, но плохой клиент превращает короткий сбой в долгий: возвращается слишком рано и вместе со всеми.
- **Как работает:**
  - 429 — много прислали лично вы; 503 — сервер плох для всех.
  - `Retry-After` — минимум ожидания, секундами или датой.
  - Повтор: можно ли (метод или `Idempotency-Key`), есть ли смысл (код), сколько уже было (попытки, бюджет).
  - Пауза растёт вдвое, джиттер не даёт вернуться строем.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- `fetch` не повторяет; на чужом источнике `Retry-After` виден только через `Access-Control-Expose-Headers` → «раздел 429 и 503».
- Заголовки квоты: черновик IETF `RateLimit` (сколько секунд) против `X-RateLimit-*` GitHub (момент Unix) → «раздел Заголовки квоты».
- Ключ: адрес, пользователь, токен или сочетание; `X-Forwarded-For` читать справа налево → «раздел Ключ лимита».
- Счётчик в памяти на N экземплярах — N лимитов; общий в Redis → «раздел Лимит на кластере».
- Четыре вида пауз: без джиттера, полный, равный, декоррелированный → «раздел Пауза и джиттер».
- Бюджет повторов и предохранитель против массового сбоя → «раздел Бюджет повторов».
- Умолчания undici, TanStack Query, ky, axios-retry расходятся → «раздел Готовые клиенты».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Ждать `Retry-After` ровно — вернуть стадо; добавлять случайную часть сверху.
- `Date.parse('1.5')` даёт 2001 год: дату разбирать, только если есть буквы.
- Первый адрес в `X-Forwarded-For` пишет клиент — лимит по нему обходится.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Три экземпляра, лимит 10: в памяти прошли 30 из 30, в Redis — 10 → «раздел Лимит на кластере».
- `INCR` и `PEXPIRE NX` — в одной транзакции → «раздел Лимит на кластере».
- Без джиттера последний из 50 клиентов ждёт 51,7 с при сбое в 2 с → «раздел Стадо после сбоя».
- Три повтора во время сбоя: 1543 запроса вместо 400 → «раздел Бюджет повторов».
- undici `RetryAgent`: 5 повторов, 500 мс × 2ⁿ, без джиттера, `Retry-After` срезается до 30 с → «раздел Готовые клиенты».
- axios-retry по умолчанию: пауза ноль, 429 не повторяет → «раздел Тонкие места».

</details>
