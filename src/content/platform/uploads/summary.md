<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** способы отправить файл обычным HTTP: одним телом `multipart/form-data`, кусками с докачкой (tus) или напрямую в хранилище по ссылке с подписью.
- **Зачем:** способы различаются тем, кто помнит, сколько уже дошло, и через чей сервер идут байты — от этого зависит судьба загрузки после обрыва и нагрузка на ваш API.
- **Как работает:**
  - multipart: части разделены случайной границей из `Content-Type`.
  - tus: `POST` создаёт загрузку, `PATCH` шлёт куски с `Upload-Offset`, после обрыва `HEAD` спрашивает, сколько сохранено.
  - Presigned URL: сервер проверяет права и подписывает HMAC метод, путь, хост и срок; браузер идёт в хранилище сам.
  - Сервер проверяет тип по первым байтам, размер по мере чтения, имя не превращает в путь.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Текст нормализуется в CRLF, файл идёт как есть; кавычка в имени → `%22`; Node и Chromium разбирают по-разному → «раздел Тело multipart».
- Прогресс есть у `xhr.upload`, у `fetch` нет; 100% — не «сервер принял»; подписка на `upload` добавляет preflight → «раздел Прогресс».
- `409` при чужом смещении; докачка после перезагрузки по отпечатку в `localStorage` → «раздел Докачка».
- Что подписано в ссылке, а что нет; CORS у бакета → «раздел Прямо в хранилище».
- Сигнатуры PNG, JPEG, GIF, PDF, WebP; `413` по пределу → «раздел Проверки на сервере».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `Content-Type: multipart/form-data` руками — без `boundary`, сервер не найдёт частей.
- Chromium сам повторил PATCH на переиспользованном соединении — защищает только сверка смещения.
- Ссылка для `PUT` не ограничивает размер и (без `SignedHeaders`) тип; ключ объекта выбирает сервер.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Граница: undici `----formdata-undici-0…`, Chromium `----WebKitFormBoundary…` → «раздел Тело multipart».
- Медленный сервер: на 100% прочитано около 7 МиБ из 8 → «раздел Прогресс».
- Обрыв на 50 000-м байте куска → `HEAD` вернул `Upload-Offset: 150000` → «раздел Докачка».
- tus сверяет смещение, но не содержимое — для этого расширение `checksum` → «раздел Докачка».
- `chunkSize` у `tus-js-client` по умолчанию бесконечен; nginx `client_max_body_size` 1 МБ; SigV4 — до недели → «раздел Тонкие места».
