# Встроенный контент без сторонних кук

`platform/third-party-cookies` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** кука становится сторонней по месту запроса — фрейм или `fetch` под чужим сайтом верхнего уровня; браузеры такие куки ограничивают и делят хранилище по сайту.
- **Зачем:** одна кука, видимая во фреймах тысячи сайтов, — готовый идентификатор человека; браузеры режут связь между сайтами.
- **Как работает:**
  - Два фильтра: сначала `SameSite`, потом политика сторонних кук (её отсекает и `None`).
  - CHIPS (`Partitioned`) кладёт куку в раздел сайта верхнего уровня.
  - `localStorage`, IndexedDB, Cache Storage, `BroadcastChannel` разделены сами, без атрибутов.
  - Общая кука — только через Storage Access API по клику; иначе сессию передаёт сайт-хозяин.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Chromium по умолчанию отдаёт стороннюю куку; ограниченный Chromium и WebKit не ставят и не отдают; Firefox кладёт в раздел → «раздел Сторонняя кука».
- Ключ раздела — сайт, а не источник; разделённая кука на своём сайте чужая → «раздел CHIPS».
- Движки расходятся: отсутствие `SameSite`, `None` без `Secure`, неразделённая кука из фрейма → «раздел Уйдёт ли кука».
- Ограничение кук и разделение хранилища — разные механизмы → «раздел Разделённое хранилище».
- Разрешение не прикладывает куки само, нужен вызов на каждой загрузке; Related Website Sets уходят → «раздел Storage Access API».
- Чат, платёжная форма, SSO: `postMessage` с токеном, FedCM, редирект → «раздел Виджет без сторонних кук».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Playwright по умолчанию показывает веб без ограничений; два порта `localhost` — один сайт, сторонней куки не будет.
- `Partitioned` без `SameSite=None` Chromium из фрейма отвергает (умолчание `Lax`); без `Secure` отвергают все.
- `await hasStorageAccess()` перед `requestStorageAccess()` съедает жест в WebKit.

</details>
