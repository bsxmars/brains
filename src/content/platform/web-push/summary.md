# Web Push

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** доставка сообщения, когда ни одной вкладки сайта не открыто: ваш сервер → push-сервис браузера (FCM, autopush, Apple) → Service Worker → уведомление.
- **Зачем:** сервер не может достучаться до устройства сам; устройство держит одно соединение со своим push-сервисом.
- **Как работает:**
  - Страница по клику получает разрешение и `pushManager.subscribe` с `userVisibleOnly` и `applicationServerKey`, отдаёт подписку серверу.
  - Сервер подписывает запрос VAPID — JWT ES256 для push-сервиса.
  - Тело шифруется для одного браузера: ECDH + `auth` → HKDF → AES-128-GCM.
  - Браузер расшифровывает и будит SW событием `push`, тот показывает уведомление.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Push-сервис видит адрес, заголовки и размер, но не текст → «раздел Три участника».
- Подписка: `endpoint`, `p256dh`, `auth`; отказы без `userVisibleOnly`, без ключа, в инкогнито → «раздел Подписка».
- `aud` — origin push-сервиса, `exp` не дальше суток; чужой ключ — 403, без подписи — 401 → «раздел VAPID».
- Заголовок aes128gcm по байтам, сверка с примером RFC 8291 → «раздел Шифрование тела».
- `TTL`, `Urgency`, `Topic`; 404/410 — удалить подписку → «раздел Доставка».
- `waitUntil`, `tag`, `notificationclick` → «раздел Событие push».
- iOS только для приложения на экране «Домой»; отказ в разрешении запоминается → «раздел Где push не дойдёт».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `201` — «принято в очередь», а не «показано»: сообщение с `TTL: 0` при выключенном устройстве пропадёт молча.
- Сменили ключ VAPID — все старые подписки получат 403.
- `Topic` заменяет недоставленное, `tag` — уже показанное; свежая подписка FCM иногда сначала отвечает 410.

</details>
