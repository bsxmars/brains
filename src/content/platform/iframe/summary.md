# iframe: чужой и свой документ внутри страницы

`platform/iframe` · выжимка составлена с ИИ 2026-11-05 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** `<iframe>` показывает внутри страницы отдельный документ со своим адресом, `window`, DOM и источником.
- **Зачем:** показать чужое (оплата, видео, карта, чат) или не подпустить чужое к своему (письмо, песочница кода).
- **Как работает:** доступ решает правило одного источника — свой фрейм открыт целиком, у чужого остаются `postMessage`, запись `location` и ссылки на окна; договариваются сообщениями с проверкой `event.origin` и `event.source`; `sandbox` отнимает способности, флаги `allow-*` возвращают их по одной, `allow` раздаёт права вроде полного экрана.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- `src` — документ по адресу, `srcdoc` — из строки с источником родителя; `title` для чтения с экрана; размер по умолчанию 300 × 150; `loading="lazy"` не грузит фрейм до прокрутки → «раздел Как встроить».
- `contentWindow` и `contentDocument`; у чужого окна 13 доступных свойств, остальное — `SecurityError`; у своего фрейма свои встроенные объекты, `instanceof` не работает → «раздел Свой и чужой».
- `postMessage(data, targetOrigin)`: строгая проверка `origin`, проверка `source`, адресат вместо `'*'`, «готов» от фрейма вместо `load`; данные копией, для долгого разговора — порт → «раздел postMessage».
- Песочница без `allow-same-origin` даёт источник `"null"`: нет хранилищ, кук и доступа снаружи; остальные флаги и `sandbox.supports()` → «раздел Песочница».
- `allow` — Permissions Policy для одного фрейма; чужой фрейм без клика не уводит вкладку; `referrerpolicy`; `credentialless` есть только в Chromium → «раздел Права фрейма».
- Высоту сообщает сам фрейм: `ResizeObserver` внутри и `postMessage` наружу → «раздел Высота».
- Переходы фрейма пишутся в историю вкладки; клавиши во фрейме не доходят до родителя → «раздел История и клавиатура».
- Фрейм своего сайта делит поток с родителем; когда фрейм не нужен → «раздел Цена».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `postMessage(секрет, '*')` уйдёт любому документу, который сейчас во фрейме; адресат `'null'` для песочницы — `SyntaxError`, остаётся только `'*'`.
- Проверка `origin.includes(...)` пропускает `shop.example.evil.example`.
- `allow-scripts allow-same-origin` у содержимого своего источника: фрейм снимает `sandbox` и перезагружается.
- Чужой HTML в `srcdoc` без `sandbox` — XSS: источник у `srcdoc` ваш.
- «Назад» листает фрейм; служебные переходы — `location.replace` или замена тега.
- `scrollHeight` не даёт фрейму сжаться; `min-height: 100vh` внутри раздувает его без конца.
- Сообщение, пришедшее до подписки, потеряно.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `document.cookie` в непрозрачном источнике: `SecurityError` в Chromium и Firefox, пустая строка в WebKit; WebKit без `allow-forms` запускает `submit`, но форму не шлёт → «раздел Песочница».
- `window.open` без `allow-popups`: `null` или `InvalidAccessError` (Firefox) → «раздел Песочница».
- `referrerpolicy="unsafe-url"` отдаёт полный адрес только в Chromium → «раздел Права фрейма».
- При замене тега Firefox удаляет записи старого фрейма из истории → «раздел История и клавиатура».

</details>
