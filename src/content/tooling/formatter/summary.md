# Форматтер изнутри

`tooling/formatter` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** Prettier не правит файл, а печатает его заново из дерева под ширину.
- **Зачем:** закрыть споры о виде кода одной процедурой печати вместо правил.
- **Как работает:** парсер → AST → Doc (текст, группы, места переносов; ширины ещё нет) → печатник идёт слева направо и для каждой группы решает: влезает в остаток строки — плоско, нет — ломается целиком, не возвращаясь назад.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Doc описывает все раскладки сразу; группы вложены как узлы дерева → «раздел От кода к Doc».
- Ширина ломает группы снаружи внутрь, `breakParent` — изнутри наружу; `fits` учитывает и хвост после группы → «раздел Печать по ширине».
- Неделимый текст остаётся длиннее `printWidth`; ширина — в колонках экрана, а не в `length` → «раздел Ширина строки».
- Из исходника остаются пустые строки, перенос после `{` у объекта и комментарии → «раздел Что остаётся».
- ESLint — ошибки, Prettier — форма; конфликты гасит `eslint-config-prettier` → «раздел Форматтер и линтер».
- Второй прогон меняет файл, только если вывод дал другой Doc — обычно из-за комментариев → «раздел Идемпотентность».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Объект, раскрытый из-за длины, сам не свернётся: перенос после `{` теперь в файле.
- Сломать внутренний вызов, оставив внешний в строку, нельзя — только вынести в переменную.
- Обновление Prettier даже на патч — переформатирование: версию фиксируют точно.

</details>

<summary><b>Детали</b> — не учить, смотреть в теме</summary>
