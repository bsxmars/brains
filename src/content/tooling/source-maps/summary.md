# Source maps изнутри

`tooling/source-maps` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** JSON рядом с бандлом: каждому куску кода — файл, строка и колонка исходника.
- **Зачем:** после сборки позиция из стека указывает в бандл, где читать нечего. Карту читают потом — отладчик, Node, сервис ошибок; код без неё работает так же.
- **Как работает:** `mappings` — строки через `;`, сегменты через `,`; сегмент — 4–5 чисел Base64 VLQ, каждое — разница с предыдущим; в строке бинарным поиском ищут последний сегмент не правее колонки.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Пути `sources` считаются от адреса карты → «раздел Что лежит в .map».
- Ссылка — комментарием или заголовком; без DevTools браузер карту не качает → «раздел Что лежит в .map».
- Колонка бандла обнуляется на каждой строке, остальное копится; сегмент из одного числа — обвязка → «раздел Сегменты и VLQ».
- `error.stack` в коде — позиции бандла, переводит только консоль DevTools → «раздел От стека к исходнику».
- Шаг без входной карты ведёт в промежуточный файл; карты склеивают → «раздел Цепочка сборщиков».
- Публичная, скрытая или никакой — кому видны исходники → «раздел Карты в продакшене».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Колонка в стеке с единицы, в карте с нуля — промах ломается на начале сегмента.
- Карта от другой сборки даёт правдоподобные чужие строки — хранить по релизу.
- Публичная карта с `sourcesContent` отдаёт исходники целиком.

</details>
