# Микрофронтенды и Module Federation

`tooling/module-federation` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** загрузка модуля чужой сборки по адресу во время работы плюс договор, чья копия общей зависимости работает.
- **Зачем:** микрофронтенды покупают независимый выкат частей интерфейса; цена — интеграция в браузере пользователя, лишние байты, общий документ.
- **Как работает:** remote кладёт контейнер `remoteEntry.js`; host грузит его, передаёт общий shareScope в `init`, просит модуль через `get` и получает фабрику; каждая сборка кладёт в shareScope свои версии и выбирает одну по своим правилам.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Способы собрать страницу: npm-пакеты, iframe, веб-компоненты, `import()`, import maps, федерация → «раздел Зачем и чем платят».
- Контейнер маленький, модули отдельно; нужна асинхронная граница `bootstrap` → «раздел Контейнер: init и get».
- Две копии React даже одной версии ломают хуки — поэтому singleton → «раздел Общие зависимости».
- Упавший и зависший remote, повтор загрузки, рассинхрон выкатов, кеш контейнера → «раздел Устойчивость».
- Типов remote у host нет; контракт — пропсы и события; один каскад стилей и один URL → «раздел Контракты и стили».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Singleton без `strictVersion` молча переводит host на чужой мажор; строгий — роняет host, если тот не взял копию через `eager`.
- Неудачный `import()` запоминается в module map — повторять только с другой меткой в адресе.
- Закешированный `remoteEntry.js` и удалённые старые чанки дают `ChunkLoadError`.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Флаги `shared`: `requiredVersion`, `singleton`, `strictVersion` (по умолчанию строго, если не singleton), `eager` → «раздел Общие зависимости».
- Ошибка двух копий: `Cannot read properties of null (reading 'useState')`; подсказка только в отладочной сборке → «раздел Общие зависимости».
- Одну версию от двух сборок выбирают: `eager` побеждает, затем имя сборки больше по строке → «раздел Тонкие места».
- `remoteEntry.js` — `no-cache`, чанки с хешем — `immutable`; без CORS — `Failed to fetch dynamically imported module` → «раздел Устойчивость».

</details>
