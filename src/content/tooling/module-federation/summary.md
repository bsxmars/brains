# Микрофронтенды и Module Federation

`tooling/module-federation` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** загрузка модуля чужой сборки по адресу во время работы плюс договор, чья копия общей зависимости работает.
- **Зачем:** микрофронтенды покупают независимый выкат частей интерфейса; цена — необходимость пережить непроверенные сочетания релизов в браузере, лишние байты, общий документ.
- **Как работает:** remote кладёт контейнер `remoteEntry.js`; host грузит его, передаёт общий shareScope в `init`, просит модуль через `get` и получает фабрику; каждая сборка кладёт в shareScope свои версии и выбирает одну по своим правилам.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Способы собрать страницу: npm-пакеты, iframe, веб-компоненты, `import()`, import maps, федерация → «раздел Зачем и чем платят».
- Контейнер может грузиться скриптом webpack либо нативным import(); транспорт и протокол init/get — разные уровни. Контейнер маленький, модули отдельно; нужна асинхронная граница `bootstrap` → «раздел Контейнер: init и get».
- Если хуки компонента и рендерер используют разные копии React, номер версии не спасает; их связывают с одной копией → «раздел Общие зависимости».
- Упавший и зависший remote, повтор загрузки, рассинхрон выкатов, кеш контейнера → «раздел Устойчивость».
- Типы remote можно доставить генератором или пакетом контрактов, но выкат способен опередить их; контракт — пропсы и события; один каскад стилей и один URL → «раздел Контракты и стили».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Singleton без strictVersion может выбрать чужой мажор с предупреждением; строгий — роняет host, если host ещё не потребил подходящую копию раньше remote.
- Неудачный `import()` запоминается в module map — повторять только с другой меткой в адресе.
- Закешированный `remoteEntry.js` и удалённые старые чанки дают `ChunkLoadError`.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- eager обеспечивает синхронную доступность; версию фиксирует первое consume. В стенде eager связан также с ранним импортом host.
- Флаги `shared`: `requiredVersion`, `singleton`, `strictVersion` (по умолчанию строго, если не singleton), `eager` → «раздел Общие зависимости».
- Ошибка двух копий: `Cannot read properties of null (reading 'useState')`; подсказка только в отладочной сборке → «раздел Общие зависимости».
- Одну версию от двух сборок выбирают: `eager` побеждает, затем имя сборки больше по строке → «раздел Тонкие места».
- `remoteEntry.js` — `no-cache`, чанки с хешем — `immutable`; ESM-remote без CORS — Failed to fetch dynamically imported module → «раздел Устойчивость».

</details>
