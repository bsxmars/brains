# Git изнутри

`tooling/git-internals` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** неизменяемые объекты, названные хешем содержимого, плюс подвижные файлы-ссылки.
- **Зачем:** одинаковое хранится один раз, порчу видно по хешу, хеш коммита ручается за весь проект.
- **Как работает:** объект — заголовок «тип длина\0» + байты, имя — SHA-1 от всего; дерево перечисляет блобы и поддеревья, коммит — дерево, родителей, автора, время; ветка — файл с хешем, `HEAD` — имя ветки; команды пишут объекты и переписывают ссылки.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Коммит пишет только изменённое и путь до корня → «раздел Дерево и коммит».
- Коммит двигает ветку, а не `HEAD`; индекс — черновик следующего коммита, блобы пишутся уже на `git add` → «раздел Ветки и индекс».
- Общий предок и три снимка; fast-forward против коммита с двумя родителями → «раздел Слияние».
- Rebase создаёт новые коммиты с новыми хешами и переписывает ссылку → «раздел Rebase».
- `reset` ничего не удаляет; удаляет только `git gc` недостижимое; packfile хранит дельты → «раздел Reflog и pack».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Длина в заголовке — в байтах, не в символах: кириллица даёт другой хеш.
- `git diff a b` сравнивает вершины; что принесёт слияние — `a...b` от общего предка.
- Rebase опубликованной ветки дублирует правки у коллег; секрет коммитом не удалить — старый блоб остаётся.

</details>
