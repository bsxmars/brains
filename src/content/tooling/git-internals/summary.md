# Git изнутри

- Git хранит снимки через неизменяемые объекты: blob содержит байты файла, tree — имена и связи, commit — корневое дерево, родителей и метаданные.
- Хеш связывает идентичность объекта с его содержимым. Изменение снимка или метаданных создаёт другой commit; одинаковые объекты могут переиспользоваться.
- Ветка — подвижная ссылка на commit, а HEAD обычно указывает на текущую ветку. Тег закрепляет выбранный объект; аннотированный тег имеет и собственные метаданные.
- Рабочая папка, индекс и последний commit — разные состояния. Add подготавливает содержимое следующего снимка, commit сохраняет его и сдвигает ссылку ветки.
- Переписывание истории создаёт новые объекты и перемещает ссылки. Перед reset, rebase и принудительной отправкой понимайте, какие снимки должны остаться достижимыми и кто уже использует прежнюю историю.
