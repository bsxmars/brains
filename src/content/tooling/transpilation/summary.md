# Транспиляция и полифилы

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** транспиляция заменяет неподдерживаемый синтаксис; полифил добавляет реализацию API при запуске.
- **Зачем:** `items?.at(-1)` содержит две независимые зависимости. Файл может успешно разбираться после Babel и падать при вызове отсутствующего `at`.
- **Как работает:** browserslist раскрывает запрос в версии; по самым старым целям и двум таблицам выбираются преобразования Babel и модули core-js. Одной неподдерживающей цели хватает для преобразования всего файла.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Ошибка синтаксиса останавливает файл до выполнения; отсутствующий метод заметен только на дошедшей до него ветке → «Переписать или дописать».
- Цели проверяются по таблицам поддержки; неизвестная цель может выпасть, пустой набор целей включает все преобразования → «От запроса к плагинам».
- Цена понижения — проверки, временные переменные и хелперы. bugfixes позволяет исправить отдельную ошибку движка вместо полного преобразования → «Во что превращается синтаксис».
- `usage` вставляет импорты по встреченным обращениям, `entry` раскрывает общую точку входа core-js под цели → «Полифилы и core-js».
- Прокси, слабые ссылки и некоторые возможности RegExp требуют поддержки движка; успешная сборка не доказывает совместимость → «Чего не сделать».
- esbuild и tsc понижают синтаксис и не устанавливают полифилы; esbuild отказывает там, где не умеет выполнить преобразование → «esbuild и tsc».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Учебный `at` должен отвергать null/undefined как получателя и BigInt как индекс: `Object(null)` и `Number(1n)` не повторяют нужные операции языка.
- `items === null` скрывает отсутствие `at`: optional chaining пропускает вызов. Нужна и непустая ветка.
- `corejs: "3"` означает 3.0 и исключает поздние модули; версия настройки должна соответствовать доступным полифилам.
- core-js может заменить существующий API, если его поведение не проходит проверку. На стенде так происходит со structuredClone и AggregateError.
- `usage` не анализирует файлы, которые не прошли через Babel, и не выводит точные типы значений по именам методов.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Одна и та же цель использует @babel/compat-data для синтаксиса и core-js-compat для API; `debug` показывает выбор.
- Проверки `null` и `undefined` разделены из-за `document.all`; приватное поле разворачивается в WeakMap и хелперы; async — в генератор с обвязкой.
- В снимке данных корзина для defaults добавляет 3 модуля при usage и 78 при entry. Числа привязаны к версиям таблиц и полифилов.
- Для исключения модуля используется `exclude: ["web.structured-clone"]`; отсутствие полифила надо сопоставить с нужным поведением приложения.

</details>
