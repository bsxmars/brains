# Монорепозиторий

- Монорепозиторий хранит несколько пакетов в общей истории. Workspaces связывают локальные зависимости, а граф задач определяет порядок и объём сборки.
- Граф пакетов и граф задач различаются: один пакет может иметь несколько команд, а команда — зависеть от результата другой. Циклы мешают простому топологическому порядку.
- Для изменения важны и затронутый пакет, и его зависимые потребители. Фильтр только по изменённой папке может пропустить сломанный downstream-код.
- Кеш задачи корректен, когда ключ учитывает все значимые входы, включая конфигурацию, окружение и результаты зависимостей. Иначе попадание в кеш возвращает устаревший результат.
- Общий репозиторий не отменяет границы API и правила выпуска. Незадекларированная зависимость, случайно доступная через hoisting, может исчезнуть при другой раскладке или публикации.
