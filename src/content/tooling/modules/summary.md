<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** ESM: `import`/`export` — объявления на верхнем уровне с путём-строкой, зависимости известны до выполнения.
- **Зачем:** отсюда предзагрузка зависимостей, ошибки связывания до запуска, живые привязки и tree shaking.
- **Как работает:** три фазы — загрузка (граф без выполнения), связывание (имена импортов становятся ссылками на чужие переменные), исполнение от листьев к корню; карта модулей по URL запоминает результат и ошибку.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- `await` наверху задерживает только зависимых; import maps со `scopes` → «раздел Три фазы».
- Импорт — живая ссылка, деструктуризация и `export default выражение` — снимки; цикл с `const` падает → «раздел Привязки и циклы».
- `require` синхронен и кеширует до выполнения; интероп `default` у Babel, Node и Vite разный; `exports` — карта и забор → «раздел CommonJS против ESM».
- Бандлер собирает нужное, а не удаляет лишнее; `sideEffects` и `/*#__PURE__*/` — обещания → «раздел Tree shaking».
- Чанки по «цвету» — набору точек входа; каскад хешей; повтор `import()` требует нового URL → «раздел Чанки и кеш».
- Dev — модули по одному с предбандлом, prod — склейка; `nomodule` для легаси → «раздел Dev не равен prod».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Цикл ломается в день, когда `function` переписали на `const`.
- Модуль с эффектом без импортов работает в dev и исчезает после сборки.
- Ложное `"sideEffects": false` выбрасывает CSS; одна версия в двух форматах даёт два экземпляра состояния.

</details>
