# Бюджеты производительности

`tooling/performance-budgets` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** число плюс правило подсчёта, проверяемое на каждый пул-реквест.
- **Зачем:** страница тяжелеет понемногу и незаметно; проверка ловит правку до прода.
- **Как работает:** входы страницы берут из HTML; строят граф чанков (из текста, манифеста Vite или metafile esbuild); обходом в ширину считают статическое замыкание и его вес; сравнивают с порогом и базовой веткой, отчёт — в пул-реквест.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Сырые против сжатых, критический путь против всех чанков, JS отдельной строкой от CSS и шрифтов → «раздел Какие байты».
- Сторож сайта: пороги по имени страницы, вес — замыкание, отдельная проверка на рантайм React → «раздел Живой бюджет».
- Регулярка путает импорт со строкой; воркеры выпадают из графа; сборщик может отдать граф файлом → «раздел Граф чанков».
- Обход в ширину даёт кратчайшую цепочку «кто тянет»; убрать модуль — разорвать все пути → «раздел Кто тянет».
- Lighthouse CI шумит и видит лишь скачанное; size-limit — для библиотек; RUM — после выката → «раздел Байты и метрики».
- Порог красит прогон, сравнение с базой — текст для человека; ложные срабатывания → «раздел Бюджет в CI».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Ссылки из HTML — не вес: рантайм приводит рендерер своим `import`.
- Сравнение по полному имени шумит из-за хешей; без хеша имя не уникально — одноимённые склеиваются.
- Рост общего чанка красит чужую страницу с наименьшим запасом; время — только предупреждением.

</details>
