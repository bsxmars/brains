<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** цепочка программ между написанным CSS и CSS браузера; каждая механически переписывает текст.
- **Зачем:** старые браузеры не знают нового синтаксиса, а глобальные классы конфликтуют между компонентами.
- **Как работает:** PostCSS разбирает CSS в дерево и зовёт плагины-посетители; lightningcss понижает синтаксис под targets; CSS-модули и Vue `scoped` изолируют классы переименованием или атрибутом; Tailwind выписывает слова из исходников и генерирует CSS для узнанных утилит.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Значения в дереве PostCSS — строки; изменённый узел обходят ещё раз → «раздел PostCSS и дерево».
- Понизить можно только известное при сборке; в Vite понижает минификатор → «раздел Понижение».
- Имя CSS-модуля — из хеша текста файла и номера строки; `composes`, `:global` → «раздел CSS-модули».
- `scoped`: атрибут `data-v-…` в разметке и селекторе; корень дочернего компонента общий → «раздел Vue scoped».
- Сканер читает файлы как текст, склеенный класс не видит → «раздел Сканер Tailwind».
- Вывод Tailwind — четыре слоя; правило вне слоёв сильнее любого слоя → «раздел Слои и байты».
- Равные селекторы решает порядок в собранном CSS, а его — порядок импортов → «раздел Порядок подключения».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `color-mix` с `var()` и `@layer` под старую цель не понижаются, предупреждений нет.
- В dev и в сборке с `minify: false` Vite отдаёт вложенность как написана.
- Посетитель PostCSS, реагирующий на свой результат, крутится без конца — защиты нет.

</details>
