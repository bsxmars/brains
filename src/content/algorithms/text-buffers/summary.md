# Как редактор хранит текст: строка, gap buffer, rope и piece table

`algorithms/text-buffers` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** структуры данных, в которых редактор держит документ: вставить, удалить, отдать текст, найти начало строки N.
- **Зачем:** дорого не хранить текст, а переписывать его; одна строка переписывает весь документ на каждую букву.
- **Как работает:** gap buffer держит дырку у курсора и переписывает только путь её переезда; rope — сбалансированное дерево кусков с `len` и `lines`, правка переписывает один лист; piece table — неизменный исходный буфер, растущий буфер добавлений и список кусков-ссылок.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- V8 откладывает копирование через cons-строку, но следующий `slice` её расплющивает → «раздел Одна строка».
- Gap buffer: у курсора — один символ, прыжок стоит расстояния, рост вдвое амортизирован → «раздел Gap buffer».
- Rope: поиск по позиции и по номеру строки — спуск по счётчикам; баланс как у AVL; размер листа — компромисс → «раздел Rope».
- Piece table: печать подряд удлиняет кусок, отмена — копия списка кусков; piece tree VS Code на красно-чёрном дереве → «раздел Piece table».
- `Y.Text` в Yjs — тот же список кусков, но удалённое остаётся надгробиями → «раздел Piece table».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Позиция — единица UTF-16, а не буква: можно разрезать суррогатную пару; `\r\n` — два символа на одну строку.
- Piece table не освобождает удалённое; много курсоров и «заменить всё» гоняют дырку gap buffer по всему файлу.
- Бенчмарк `s += 'x'` в V8 врёт: копирования нет до среза или чтения по индексу.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Документ 100 000: строка переписывает 100 001 на букву, первая вставка gap buffer в середину — 50 001 → «раздел Gap buffer».
- Запас дырки 2000, как `GAP_BYTES_DFL` в Emacs; 100 000 символов подряд — 2,8 переписанного на символ → «раздел Gap buffer».
- Piece table после 1000 правок: 1491 кусок, поиск строки смотрит в среднем 727 → «раздел Piece table».
- VS Code: piece tree с версии 1.21 (март 2018), поля `size_left` и `lf_left`, куски чтения по 64 КБ → «раздел Piece table».
- Rope: документ вырос в сто раз — путь с 10 до 23 узлов → «раздел Сравнение».

</details>
