# Планировщики: очередь с приоритетом и нарезка времени

`algorithms/schedulers` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** механизм, который решает, что взять следующим и когда остановиться, чтобы вернуть поток браузеру.
- **Зачем:** поток один; пока идёт долгая работа, клик ждёт. Нужна очередь, выдающая самое срочное, и цикл, вовремя отдающий поток.
- **Как работает:** приоритет превращается в срок `startTime + timeout`; задачи лежат в двоичной куче по сроку; цикл берёт задачи, пока не кончился квант; длинная задача сама спрашивает `shouldYield()` и возвращает продолжение.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Отсортированный массив проигрывает: вставка сдвигает элементы, а новые сроки почти всегда самые поздние → «раздел Очередь».
- Куча на массиве: родитель срочнее детей, ремонт — просеивание по одной ветке → «раздел Куча».
- Куча неустойчива, поэтому второй ключ — растущий `id` → «раздел Равные сроки».
- `scheduler` React: куча готовых задач по сроку и куча отложенных по времени старта, ленивая отмена, один таймер хоста → «раздел Две кучи».
- Продолжение сохраняет срок; после продолжения планировщик уступает всегда → «раздел Нарезка».
- Старение по сроку против голодания; у `scheduler.postTask` сроков и старения нет → «раздел Голодание».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `shouldYield` — вопрос, а не прерывание: вытеснения в JS нет, длинный кусок доработает до конца.
- Просроченная задача квант не спрашивает и выполняется с `didTimeout = true`; Immediate не синхронна, но не уступает вовсе.
- Массив кучи в отладчике — не порядок выполнения; отменённые задачи остаются в куче.

</details>
