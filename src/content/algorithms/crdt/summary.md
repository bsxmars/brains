# CRDT: как два редактора сливают правки без сервера

`algorithms/crdt` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** структура данных, у которой слияние реплик даёт один ответ при любом порядке — конфликт решён заранее правилом.
- **Зачем:** правка «по индексу» применяется не туда, если слева успели вставить чужое, и копии молча расходятся; CRDT сходится без сервера-диспетчера.
- **Как работает:** у символа постоянный id `[client, clock]`; вставка ссылается на соседа слева, а не на позицию; удаление — пометка (надгробие); порядок спорных вставок — одно правило над id для всех.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- OT пересчитывает индекс, порядок задаёт сервер; CRDT платит памятью → «раздел Сходимость».
- Слияние коммутативно, ассоциативно, идемпотентно; G-Counter, PN-Counter, LWW-Register, OR-Set → «раздел Простые CRDT».
- Мини-CRDT в духе RGA, правка без соседа ждёт в pending; надгробия не выбросить → «раздел Последовательность».
- State vector устроен как G-Counter: «мои часы → чего у тебя нет» → «раздел Векторные часы».
- Yjs: YATA (RGA плюс сосед справа), склейка подряд набранного, сборка мусора → «раздел Yjs».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Сходится — не значит осмысленно: одновременно набранные слова могут перемешаться.
- Курсор или комментарий как индекс поедут — привязывать к id (относительные позиции Yjs).
- LWW верит часам устройства, проигравшая правка пропадает молча; clientID обязан быть уникален.

</details>
