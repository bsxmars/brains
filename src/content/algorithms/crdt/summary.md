# CRDT: как два редактора сливают правки без сервера

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** структура данных, у которой слияние реплик даёт один ответ при любом порядке — конфликт решён заранее правилом.
- **Зачем:** правка «по индексу» применяется не туда, если слева успели вставить чужое, и копии молча расходятся; CRDT сходится без сервера, задающего общий порядок каждой правки; доставка и права доступа всё равно нужны.
- **Как работает:** у символа постоянный id `[client, clock]`; вставка ссылается на соседа слева, а не на позицию; удаление — пометка (надгробие); порядок спорных вставок — одно правило над id для всех.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- OT пересчитывает индекс, порядок задаёт сервер; CRDT платит памятью → «раздел Сходимость».
- Слияние состояний коммутативно, ассоциативно, идемпотентно; у операций нужно учитывать их зависимости; G-Counter, PN-Counter, LWW-Register, OR-Set → «раздел Простые CRDT».
- Мини-CRDT в духе RGA, правка без соседа ждёт в pending; надгробия не выбросить → «раздел Последовательность».
- State vector устроен как G-Counter: «мои часы → чего у тебя нет» → «раздел Векторные часы».
- Yjs: YATA (RGA плюс сосед справа), склейка подряд набранного, сборка мусора → «раздел Yjs».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Сходимость наступает после доставки одинакового набора допустимых обновлений. Пока клиент без связи, копии могут различаться.
- Совпавший список бронирований может превысить вместимость: строгий лимит требует отдельного протокола.
- Сходится — не значит осмысленно: одновременно набранные слова могут перемешаться.
- Курсор или комментарий как индекс поедут — привязывать к id (относительные позиции Yjs).
- LWW верит часам устройства, проигравшая правка пропадает молча; clientID обязан быть уникален.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Мини-реализация: левее больший clock, при равном — меньший client; Yjs ставит левее меньший clientID → «раздел Последовательность», «раздел Yjs».
- 2000 правок: видно 62 символа, в списке 1031 элемент, 969 надгробий → «раздел Последовательность».
- `encodeStateVector`, `encodeStateAsUpdate(doc, sv)`, `applyUpdate`, `store.pendingStructs` → «раздел Векторные часы», «раздел Yjs».
- 1000 символов: в конец — 1871 байт, вразнобой — 9028; всё удалено: `gc: true` 16 байт, `gc: false` 1877 → «раздел Yjs».
- Разница по state vector несёт все удаления: 108 байт против 15 у события `update` → «раздел Тонкие места».

</details>
