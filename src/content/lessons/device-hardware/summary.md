# Доступ к железу: Serial, USB, Bluetooth, HID и MIDI

`lessons/device-hardware` · выжимка составлена с ИИ 2026-11-03 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** пять API, которые дают странице прямой доступ к устройству: Serial, USB, Bluetooth LE, HID, MIDI.
- **Зачем:** говорить с платой, принтером, браслетом, геймпадом или синтезатором без программы-посредника.
- **Как работает:**
  1. Только в безопасном контексте и только по клику: `requestPort()` / `requestDevice()` без жеста — `SecurityError`.
  2. Устройство выбирает человек в окне браузера; сайт получает одно выбранное и не видит списка.
  3. Дальше — язык протокола: Serial — `readable`/`writable` стримы, USB — передачи, Bluetooth — характеристики GATT, HID — отчёты, MIDI — сообщения по 1–3 байта.
  4. Разрешение помнится за источником (`getPorts()`, `getDevices()`), снимается `forget()`.

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `await fetch(…)` перед `requestPort` может «съесть» жест — запрос упадёт с `SecurityError`.
- Отмена окна: Serial и USB — `NotFoundError`, HID — пустой массив без ошибки.
- Куски из `reader.read()` не совпадают со строками — копить хвост.
- `port.close()` при запертом потоке по спецификации отклоняется: сначала `reader.cancel()`.
- Bluetooth: сервис не из `filters`/`optionalServices` для сайта не существует.
- MIDI: `0x9n` с силой 0 — это «отпущена».
- `page.evaluate` в Playwright идёт с жестом — проверять отказы надо кодом в странице.

</details>
