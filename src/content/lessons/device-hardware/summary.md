# Доступ к железу: Serial, USB, Bluetooth, HID и MIDI

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- Браузер открывает канал к устройству, а формат команд и ответов задаёт его протокол. Фильтр по производителю не подтверждает совместимость прошивки.
- Разрешение и соединение — разные состояния. `requestPort` даёт объект порта, `open` открывает его, `close` освобождает соединение, `forget` отзывает разрешение.
- Serial, USB, Bluetooth и HID требуют кратковременной активации пользователя для окна выбора. Serial, USB и Bluetooth возвращают одно устройство; HID — массив, при отмене пустой.
- MIDI не использует такое окно выбора одного устройства и не требует активации пользователя по контракту API. После разрешения `requestMIDIAccess` даёт списки доступных входов и выходов.
- Владелец соединения отвечает за очистку при успехе и ошибке: освобождает читателей и писателей, интерфейсы, подписки и сам канал.

</details>

<details>
<summary><b>Карта</b> — как связаны механизмы</summary>

- **Serial:** выбрать порт → открыть с нужным `baudRate` → записать байты → декодировать UTF-8 → накопить строку до `\n` → освободить потоки → закрыть порт.
- **USB:** открыть → выбрать конфигурацию → занять интерфейс → выполнить передачи → освободить интерфейс → закрыть. Номера берутся из описания конкретного устройства.
- **Bluetooth LE:** подключить GATT → получить сервис → характеристику → прочитать значение; если поддерживаются уведомления, подписаться. Завершение снимает обработчик, останавливает уведомления и отключает GATT.
- **HID:** открыть устройство → получать отчёты с `reportId` → снять обработчик → закрыть. Формат отчётов задаёт дескриптор устройства.
- **MIDI:** получить доступ → подписаться на сообщения входов → учитывать новые порты через `statechange` → снять обработчики и закрыть использованные входы.

</details>

<details>
<summary><b>Подвох</b> — частые ошибки</summary>

- Долгий `await` перед `requestPort` может пережить активацию; вызов `button.click()` из скрипта её не создаёт.
- Кусок потока не равен строке. `TextDecoderStream` собирает разрезанные UTF-8 символы, а `readLine` отдельно собирает строку.
- Срок в `readLine` ограничивает ожидание ответа, а не длительность `open` или записи.
- Перед `port.close` нужно освободить обе блокировки. При декодировании через `pipeTo` недостаточно отменить читателя: надо дождаться завершения перенаправления потока.
- Закрытие USB должно произойти и после ошибки передачи, и после ошибки `releaseInterface`.
- Bluetooth-характеристика может поддерживать чтение без уведомлений; сервисы вне запроса сайту недоступны.
- MIDI `0x9n` с силой 0 означает отпускание ноты. Не все MIDI-сообщения состоят из трёх байт.
- `Permissions-Policy` не выдаёт пользовательское разрешение, а разрешение не отменяет запрет политики.

</details>

<details>
<summary><b>Детали</b> — смотреть по необходимости</summary>

- Таблица поддержки — снимок Chromium 153, Firefox 155 и WebKit 26.6. Наличие API не подтверждает доступ к любой периферии.
- Нативные тесты исполняют Serial на тестовом порту Firefox и Bluetooth на устройстве DevTools. Новое Bluetooth-уведомление этот стенд не отправляет.
- USB/HID после выбора проверяются подставными объектами: это проверка логики очистки, не обмена с настоящим железом.
- Blocklist ограничивает защищённые интерфейсы и сервисы даже при согласии пользователя. Sysex MIDI требует отдельного уровня разрешения.
- В Playwright `page.evaluate` может выполняться с активацией. Проверки отказа без жеста размещают в скрипте страницы.

</details>
