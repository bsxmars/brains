# Промис изнутри

`lessons/promise-internals` · выжимка обновлена 2026-11-11 по тексту темы.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- Промис хранит состояние и результат. Пока он pending, реакции ждут в списках; после завершения ставятся микрозадачами. У уже завершённого промиса `.then` ставит реакцию в очередь при подписке.
- `.then` всегда возвращает новый промис цепочки. Возвращённое обработчиком значение становится его результатом, а исключение — причиной отказа. Исходный промис не меняется.
- Несколько подписок на один промис получают один исходный результат. В цепочке следующее звено получает результат предыдущего.

</details>

<details>
<summary><b>Карта</b> — как объяснить порядок</summary>

- `PerformPromiseThen` добавляет реакцию: в список для pending или сразу в очередь для settled.
- `resolve(x)` принимает результат для уже существующего промиса. Если x — промис или объект с методом then, завершение зависит от его ответа.
- `PromiseResolve(C, x)` получает промис для значения. Для обычного промиса того же конструктора дополнительная обёртка не нужна; на этом основано отличие `await p` от возврата p из обработчика.
- Тики линейки показывают порядок шагов очереди, а не миллисекунды. Для разобранного примера `return p` даёт 3 тика, `return await p` — 2.
- Схема жизненного цикла показывает списки и очередь одного промиса. Она не измеряет память и не отображает все создаваемые промисы цепочки.

</details>

<details>
<summary><b>Подвох</b> — как управлять работой</summary>

- `all`, `allSettled`, `race`, `any` собирают результаты по разным правилам. Они не отменяют уже запущенные операции и не ограничивают их число.
- `await` внутри цикла обычно даёт последовательное выполнение. Для одновременного запуска операции создают до ожидания результатов; для ограничения числа запусков нужен пул.
- Промис описывает результат, а отменяют саму операцию — например, через `AbortSignal`.
- Подписку на отказ нужно добавлять сразу: поздний `catch` может появиться уже после сообщения об необработанном отказе.

</details>

<details>
<summary><b>Детали</b> — смотреть по необходимости</summary>

- Отказ проходит через звенья цепочки без обработчика. `.then` может пометить исходный промис обработанным и перенести необработанный отказ на новый.
- `return await` внутри `try` позволяет поймать отказ ожидаемого промиса; `return` в самом `finally` может перекрыть результат или ошибку.
- Чтение then у постороннего объекта может выполнить геттер. Сравнение значений, thenable и промисов раскрыто отдельным экспериментом.
- Pending-промис, который где-то хранится, удерживает реакции и их замыкания. Ненужный промис, до которого нет путей от корней, может быть собран вместе с ними.
- Микробенчмарки создания и ожидания промисов — дополнительный материал: не путать число микрозадач с процессорной стоимостью.

</details>
