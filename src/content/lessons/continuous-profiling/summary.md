# Непрерывное профилирование памяти

`lessons/continuous-profiling` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** выборочный профиль выделений и метрики процесса, всегда включённые на боевом сервисе.
- **Зачем:** снимок кучи останавливает сервер и раздувает память; выборка почти бесплатна и называет выделяющую функцию.
- **Как работает:** V8 отмеряет случайное число байт и пишет стек попавшего выделения; стеки сливают в flame graph; цена — по числу сэмплов.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Два режима: по умолчанию «только живое» (где родилось дожившее), с флагами — все выделения (кто мусорит) → «раздел Вместо снимка».
- Профиль называет место рождения, а не держателя → «раздел Вместо снимка».
- Крупный объект попадает в выборку почти всегда, мелкий — редко → «раздел Цена выборки».
- CPU-профиль считает по времени, профиль выделений — по байтам → «раздел Flame graph».
- Загрузка и задержка цикла ловят разное, нужны обе → «раздел Метрики».
- Утечку от кеша отличает пол кучи после major GC → «раздел Метрики».
- Агенты шлют профили окнами с метками; версии сравнивают по долям → «раздел Практика».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Алерт на частоту major GC пропустит утечку: V8 отодвигает порог, сборок меньше, чем у кеша.
- Встроенная (inlined) функция без кадра — выделение уходит вызывающему.
- Гистограмма задержки в простое показывает шаг опроса, а не ноль.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Интервал по умолчанию: протокол `HeapProfiler.startSampling` — 32 КБ, `v8.startHeapProfile` (только Node 26) — 512 КБ → «раздел Тонкие места».
- Формулы: сэмплов/с ≈ скорость выделения / интервал; вероятность `1 − e^(−s/интервал)`; разброс `1/√n` → «раздел Цена выборки».
- Накладные: 512 КБ — шум, 32 КБ — ×1.04–1.11, 64 Б — ×13–20 → «раздел Цена выборки».
- `eventLoopUtilization`, `monitorEventLoopDelay`, `PerformanceObserver('gc')` с `detail.kind`, `v8.GCProfiler` → «раздел Метрики».
- Pyroscope, Datadog — живая куча; Parca — eBPF, CPU → «раздел Практика».
- `measureUserAgentSpecificMemory` только при COOP+COEP, ответ ждёт сборки → «раздел Браузер».

</details>
