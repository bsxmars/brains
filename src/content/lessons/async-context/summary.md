# Асинхронный контекст: AsyncLocalStorage и AsyncContext

- Асинхронный контекст связывает данные с цепочкой работы, например с запросом. Обычная глобальная переменная не подходит: перекрывающиеся операции начинают видеть чужое значение.
- AsyncLocalStorage.run задаёт область контекста, а getStore читает текущее значение. Возврат из run и продолжение созданной внутри асинхронной работы имеют разные сроки жизни.
- Перенос контекста зависит от API и места создания или привязки продолжения. Сам объект функции не сохраняет нужный контекст только потому, что был объявлен внутри области.
- Для неподдерживаемой границы может потребоваться явная привязка или AsyncResource. Проверяйте реальную цепочку вызовов, а не только соседство await в исходнике.
- Контекст не обеспечивает авторизацию и не изолирует изменяемые объекты хранилища. Не удерживайте там большие ресурсы дольше запроса и не позволяйте записи одной операции менять данные другой.
