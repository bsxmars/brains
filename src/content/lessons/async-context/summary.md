# Асинхронный контекст: AsyncLocalStorage и AsyncContext

`lessons/async-context` · выжимка по актуальному тексту темы, 2026-11-11.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** значение, связанное с цепочкой асинхронной работы. Когда и переносится ли оно вообще, определяет API.
- **Зачем:** id запроса нужен в каждом слое. Передавать его параметром утомительно, а глобальная переменная врёт: после `await` там лежит id чужого перекрывшегося запроса.
- **Как работает:** `als.run(value, fn)` задаёт значение на время `fn`, а `getStore()` читает его откуда угодно. Продолжения промисов и таймеры поддерживают перенос контекста. Обычный синхронный вызов функции сам его не сохраняет. С Node 24 значения лежат в одном неизменяемом кадре, и через промисы его переносит сам V8.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Для ошибки глобального id достаточно двух перекрывшихся запросов → «раздел Гонка».
- `enterWith` задаёт значение без `run` вокруг и протекает наружу → «раздел AsyncLocalStorage».
- Снимок берёт подписка (`then`/`await`), а не создание промиса. `EventEmitter` снимка не берёт → «раздел Момент снимка».
- Старая реализация на `async_hooks` платит за каждый асинхронный ресурс процесса, у новой нет этих JS-вызовов _propagate; это не обещание нулевой цены await → «раздел Внутри Node».
- Обёртку можно собрать подменой `then`/`setTimeout`, но родной `await` её обходит. В то же ограничение упирается zone.js → «раздел Своими руками».
- В браузерах стенда глобального `AsyncContext` нет. Предложение пока черновик, а фреймворки обходятся подменой, компилятором или ничем → «раздел Браузер».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `enterWith` в слушателе отдаёт значение соседним слушателям и коду после `emit`. В `async`-функции до первого `await` он меняет контекст вызывающему.
- Колбэк чужого пула или сокета может выполняться в контексте этого ресурса вместо своего запроса. Лечится `AsyncResource.bind(fn)` в момент, когда колбэк отдаёшь.
- Хранилище может содержать любое значение. Если это объект, snapshot сохраняет ссылку, а не копию его полей; поздняя мутация видна и уже захваченному контексту.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Промис создан в A, подписан в B, разрешён в C: `then` и `await` видят B, таймеры и `nextTick` — A → «раздел Момент снимка».
- Вызовы хука на один запрос: 0 в новой реализации, 8 в старой (6 промисов и 2 таймера), 16 при втором хранилище. Старая включается флагом `--no-async-context-frame` → «раздел Внутри Node».
- Подменённый `then` при `await` вызывается 0 раз, при `Promise.all` из двух промисов — 2 раза → «раздел Своими руками».
- Экспериментальный `withScope` для `using` есть в Node 24.20 и 26.8.2. До первого await он тоже способен изменить контекст вызывающего; для async предпочитайте run → «раздел AsyncLocalStorage».
- Соответствия в `AsyncContext`: `Variable`, `Snapshot`, `Snapshot.wrap`. Аналога `enterWith` нет, предложение в Stage 2 → «раздел Браузер».
- Vue оборачивает await верхнего уровня в script setup в `withAsyncContext`. OpenTelemetry без менеджера контекста пуст даже синхронно → «раздел Браузер».

</details>
