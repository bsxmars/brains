# Ошибки и стеки

`lessons/errors` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** ошибка — обычный объект: `name` (из прототипа), `message`, `stack`, `cause`; стек — снимок вызовов в момент `new Error`.
- **Зачем:** у пользователя это единственный свидетель: что, где и почему упало.
- **Как работает:** кадры V8 снимает в конструкторе, строку `stack` — при первом чтении; после `await` достраивает кадры `at async …` по цепочке промисов; непойманное получает среда; отчёт собирают явным обходом.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- `message`, `stack`, `cause` неперечисляемые, поэтому `JSON.stringify(err)` во фронте даёт `{}`; отчёт собирают явно, поле за полем; у системных ошибок Node `code`, `errno`, `syscall`, `path` — обычные поля, их JSON видит → «раздел Объект ошибки».
- Стек можно снять заново без обвязки, ограничить и получить кадрами-объектами → «раздел Когда снимается стек».
- Асинхронный стек виден только по цепочке `await` и `Promise.all`-семейства → «раздел Асинхронный стек».
- Браузер сообщает событием и живёт; чужой скрипт без CORS даёт «Script error.»; Node печатает и завершает процесс → «раздел Необработанные».
- `finally` подменяет летящую ошибку или результат; `using` сохраняет обе → «раздел finally».
- Отчёт: цепочка причин, свои поля, обрезанный стек, разбор стека на кадры → «раздел Отчёт».

- Практики: ловить на краях (обработчик, `ErrorBoundary`), а не везде; `fetch` не бросает на 404 и 500 — проверять `res.ok`; не глотать ошибку; ловить узко и пробрасывать остальное; на границе слоя — своя ошибка с `cause`; ожидаемое — значение, неожиданное — исключение; без висящих промисов; один отчёт; уборка в `finally`; тонкие места там же → «раздел Как работать».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Стек указывает на `new Error`, а не на `throw`: ошибка, заготовленная в модуле, всегда «родилась» при загрузке.
- `.then` в обычной функции и колбэк таймера рвут асинхронный стек.
- Исключение из `finally` заменяет исходное без `cause`, `return` там глотает его.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `Error.stackTraceLimit` по умолчанию 10, читается при создании ошибки → «раздел Когда снимается стек».
- `Error.captureStackTrace(obj, fn)`; `Error.prepareStackTrace` — глобальный хук, зовётся один раз → «раздел Когда снимается стек».
- Лечение «Script error.»: `crossorigin="anonymous"` плюс `Access-Control-Allow-Origin` → «раздел Необработанные».
- Node: без обработчика код выхода 1, обработчик `uncaughtException` бросил — 7 → «раздел Необработанные».
- `SuppressedError`: `error` — закрытие, `suppressed` — заглушённая → «раздел finally».
- `structuredClone` берёт `message`, `stack`, `cause`, но теряет `errors`, `code` и подкласс → «раздел Отчёт».

</details>
