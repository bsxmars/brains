# Голос: запись с микрофона и речь

`lessons/media-voice` · выжимка составлена с ИИ 2026-11-03 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** микрофон в браузере — живой поток; `MediaRecorder` сжимает его в файл кусками; речь — отдельный Web Speech API.
- **Зачем:** голосовые заметки, голосовой ввод, озвучка интерфейса.
- **Как работает:**
  1. `getUserMedia({ audio: true })` спрашивает разрешение и отдаёт `MediaStream` — только на `https` или `localhost`.
  2. `new MediaRecorder(stream).start(timeslice)` — куски в `dataavailable`; склеенные по порядку — файл в `Blob`.
  3. Микрофон отпускает `track.stop()`, а не `recorder.stop()`.
  4. Синтез `speechSynthesis` — голоса системы, локально; распознавание `SpeechRecognition` в Chrome по умолчанию — на сервере.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Уровень громкости — `AnalyserNode` → тема «Звук: Web Audio API».
- Голоса и `voiceschanged`, очередь и `cancel` → «раздел Синтез речи».
- `processLocally`, `available()`, `install()` → «раздел Распознавание».
- Склейка кусков на сервере по номеру → «раздел На сервер».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Остановили запись, а индикатор горит: дорожка жива.
- У записи `duration` — `Infinity`: заголовок пишется до того, как длина известна.
- Кусок из середины — не файл: заголовок только в первом.
- Пропавший средний кусок ошибкой не выглядит — файл просто короче.
- Chromium не говорит без клика (`not-allowed`); Firefox и WebKit говорят.
- `getVoices()` сначала пуст.

</details>
