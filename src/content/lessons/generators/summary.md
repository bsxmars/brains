# Генераторы и асинхронные итераторы

`lessons/generators` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** функция, которая останавливается на `yield` и продолжает с того же места; объект-генератор хранит место остановки и значения переменных.
- **Зачем:** из паузы собраны `async/await`, асинхронные итераторы и `for await`; `async/await` — генератор, которого продолжает кто-то другой.
- **Как работает:** генератор отдаёт промис через `yield` → драйвер (`spawn`/`co`) ждёт его → передаёт результат в `next(v)` или отказ в `throw(e)` → `return` генератора становится `resolve` внешнего промиса.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Значение выражения `yield` выбирает тот, кто зовёт `next(x)`, а не генератор → «раздел Пауза генератора».
- Без поддержки движка генератор — это `switch` по номеру шага плюс переменные, вынесенные в замыкание → «раздел Пауза генератора».
- `await` устроен как генератор под `spawn`; сегодня этот цикл пишут компиляторы (`__awaiter`, `_asyncToGenerator`) и библиотеки вроде redux-saga → «раздел async/await из генератора».
- Асинхронный итератор: `next()` возвращает промис `{ value, done }`; `for await` не просит следующее, пока не доработало тело → «раздел Асинхронные итераторы».
- Асинхронный генератор ставит `next`/`return`/`throw` в одну очередь; итератор, написанный руками, этого не делает → «раздел Очередь next()».
- Ранний выход зовёт `return()`, у асинхронного он возвращает промис, и цикл его ждёт → «раздел Ранний выход».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `return()` не прерывает `await` внутри генератора: он встаёт в очередь; таймаут через `Promise.race` лишь перестаёт ждать. Прерывать надо само ожидание — сигналом `AbortController`.
- `return()` — просьба: `yield` в `finally` даст `done: false`. `throw()`/`return()` до первого `next()` в тело не заходят.
- Ошибка из `finally` теряется, если тело `for await` уже бросило.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- TS `target: ES5` → `__generator`, `_a.label`, `_a.sent()` → «раздел Пауза генератора».
- TS ниже ES2017 → `__awaiter`, Babel → `_asyncToGenerator`: обе — та же `spawn` → «раздел async/await из генератора».
- У собранного под ES2016 кода кадров `at async` в стеке нет → «Ошибки и стеки», раздел «Асинхронный стек».
- Повторный `next()` изнутри обычного генератора → `TypeError: Generator is already running` → «раздел Очередь next()».
- `Symbol.asyncIterator`, `[object AsyncGenerator]` → «раздел Асинхронные итераторы».

</details>
