# Event Loop

`lessons/event-loop` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** механизм хоста (браузер по HTML Standard, Node через libuv), который решает, какой код выполнится следующим; в ECMAScript есть только Job Queue и run-to-completion.
- **Зачем:** поток один, а ожидания внешнего мира много; выбрана кооперативная однопоточность — блокировки не нужны, но поток надо быстро отдавать.
- **Как работает:** цикл берёт одну задачу из любой непустой очереди → выполняет до конца → стек пуст → checkpoint: все микрозадачи до последней, включая добавленные → примерно раз в кадр рендер-шаги (rAF, style, layout, paint).

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Порядок гарантирован только внутри одного источника задач; между источниками решает браузер → «раздел Источники задач».
- Checkpoint наступает при пустом стеке, а не «после задачи»: настоящий клик и `btn.click()` из кода дают разный порядок → «раздел Checkpoint».
- MutationObserver — микрозадача; ResizeObserver/IntersectionObserver и rAF — нет; `nextTick` — своя очередь раньше промисов → «раздел Checkpoint».
- Задержка таймера — нижняя граница; вложенные таймеры клампятся, в фоне троттлинг → «раздел Таймеры».
- В Node оборот разбит на фазы, порядок между категориями предсказуем; CJS и ESM различаются на старте → «раздел Node».
- Часть работы Node идёт в общий пул потоков libuv, сеть — нет → «раздел Node».
- У вкладки и у каждого воркера свой цикл (агент); унести работу с главного цикла может только воркер → «раздел Агенты».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Микрозадачи не «быстрее»: рекурсивный `queueMicrotask` (в Node — `process.nextTick`) вешает вкладку/процесс; дробить работу надо задачами.
- `setTimeout(0)` против `setImmediate` в теле файла Node — гонка; внутри колбэка I/O `setImmediate` всегда первым.
- `nextTick`, вызванный из микрозадачи (после `await`), выполнится после микрозадач, а не раньше.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Кламп 4 мс — с седьмого таймера цепочки (вложенность > 5); к `MessageChannel` не применяется → «раздел Таймеры».
- Фон: таймеры не чаще раза в секунду, через ~5 минут цепочки таймеров — раз в минуту; задержка > 2 147 483 647 мс → 1 мс и `TimeoutOverflowWarning` → «раздел Таймеры».
- Фазы Node: timers → pending callbacks → idle, prepare → poll → check → close callbacks → «раздел Node».
- Пул libuv: 4 потока (`UV_THREADPOOL_SIZE`), туда fs, `dns.lookup`, `crypto.pbkdf2`, zlib → «раздел Node».
- `throw` из `queueMicrotask` → событие `error`, из промиса → `unhandledrejection` → «раздел Checkpoint».
- `requestIdleCallback`: `timeRemaining()` обычно ≤ 50 мс, опция `timeout` и флаг `didTimeout` → «раздел Источники задач».

</details>
