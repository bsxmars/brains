# Копирование и сериализация: JSON и structuredClone

<details>
<summary><b>Ядро</b> — что считать копией</summary>

- Спред создаёт новый внешний объект со значениями собственных перечислимых свойств. Вложенные ссылки остаются общими. Для обновления одного товара копируют заказ, массив и изменяемый товар; остальные ссылки можно сохранить намеренно.
- JSON — текстовый формат с ограниченным набором типов. Запись и чтение не гарантируют сохранение исходного значения: дата станет строкой, Set — пустым объектом, общие ссылки разделятся, цикл вызовет TypeError.
- structuredClone сохраняет поддерживаемые типы и связи графа: одна исходная запись остаётся одной записью внутри копии. Но объекты копии отличаются от оригинала; два отдельных вызова создают разные копии.

</details>

<details>
<summary><b>Карта</b> — основные алгоритмы</summary>

- stringify: обычное чтение → toJSON → replacer → преобразование обёрток → запись. Корень приходит с ключом `""`. toJSON возможен и у функции.
- В объекте undefined, функция или символ пропускаются; в массиве на их месте записывается null. На верхнем уровне stringify может вернуть undefined, который не является текстом JSON.
- parse с reviver обходит разобранные значения снизу вверх. Формат должен сохранить достаточно данных для восстановления типа; определить, что пустой объект раньше был Set, невозможно.
- structured clone запоминает соответствие «оригинал → копия» в memory. Для встроенных типов использует специальные правила, для обычных объектов — собственные перечислимые строковые свойства.
- Пользовательский экземпляр класса обычно становится обычным объектом. Для сохранения поведения задают формат данных и восстановление: Money.toDTO() → передача → Money.from().

</details>

<details>
<summary><b>Подвох</b> — где успешный вызов недостаточен</summary>

- Собственные перечислимые геттеры могут выполняться во время копирования. Даже отказ с DataCloneError не отменяет уже случившиеся побочные эффекты.
- Стандартный Date.toJSON вызывается раньше replacer. this[key] даёт исходное свойство, но может повторно вызвать его геттер.
- undefined из reviver удаляет элемент массива, оставляя дыру. Для фильтрации можно вернуть новый массив на шаге обработки самого массива.
- JSON.parse(JSON.stringify(undefined)) бросает SyntaxError: первый шаг не создал текст.
- Сохранённый cloneDeep прототип не восстанавливает приватные поля. Неподдерживаемые вложенные значения могут остаться ссылками на оригинал.
- Обычный AbortSignal в браузере не сериализуется; Node 26.8.2 возвращает вместо него пустой объект. Это не передача отмены.

</details>

<details>
<summary><b>Детали</b> — границы и проверка</summary>

- Дескрипторы, неперечислимые и унаследованные свойства требуют отдельного решения. Спред и assign отличаются записью в цель: assign может вызвать её сеттер.
- RegExp копируется с исходным текстом и флагами, но без lastIndex. Несколько видов одного буфера сохраняют общий буфер внутри копии.
- Transfer передаёт владение байтами и отсоединяет исходный ArrayBuffer; список задаётся как `{ transfer: [...] }`. У SharedArrayBuffer новая обёртка сохраняет общие байты, поэтому независимой памяти не получается.
- Учебные stringify и clone показывают механизм и сравниваются с настоящими API на примере. Они не являются полными реализациями: в частности, модель не покрывает JSON.rawJSON, Proxy, SharedArrayBuffer и платформенные типы.
- postMessage, IndexedDB и history.pushState используют семейство structured clone, но имеют разные ограничения.

</details>
