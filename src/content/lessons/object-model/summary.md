# Объектная модель

`lessons/object-model` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** объект — свойства (ключ → дескриптор) плюс слот `[[Prototype]]`; классы задают создание объектов, протоколы связывают их с синтаксисом, Proxy перехватывает операции.
- **Зачем:** почти все «странности» объектов — следствия одного устройства, а не причуды движка.
- **Как работает:**
  1. `[[Get]]` идёт по цепочке до первого, кто знает ключ; геттер получает `this` = объект, с которого начали.
  2. `[[Set]]` тоже проходит цепочку — ищет причину не создавать своё свойство.
  3. `class` создаёт конструктор и `prototype`; `extends` связывает и конструкторы, и прототипы экземпляров. Приватные `#`-элементы хранятся отдельно от обычных свойств.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Три причины отказа записи; поля класса и спред идут через `[[DefineOwnProperty]]` мимо цепочки → «раздел Модель», «раздел Дескрипторы».
- `[[Prototype]]` и свойство `prototype` — разные вещи; `__proto__` меняет прототип только ключом в литерале → «раздел Прототипы».
- `instanceof` вызывает `Symbol.hasInstance`, ломается между realm'ами и копиями библиотеки → «раздел Наследование».
- `super` ищет от `[[HomeObject]]`; `#`-поля — слот, а не свойство → «раздел Классы».
- Три уровня запирания, все поверхностны → «раздел Замки».
- Символ прячет от случайного кода, не от намеренного → «раздел Символы».
- Iterable предоставляет итератор через `Symbol.iterator`, iterator хранит состояние обхода → «Протокол итератора».
- Паузы генератора и `next(x)` / `throw` / `return` разобраны в теме «Генераторы и асинхронные итераторы».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Поля подкласса создаются после `super()`: метод, вызванный из родительского конструктора, их не видит, а поле затирает записанное им.
- `configurable: false` — навсегда.
- Числовые ключи встают первыми по возрастанию.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `defineProperty` по умолчанию ставит флаги `false`, присваивание — `true` → «раздел Дескрипторы».
- Матрица `preventExtensions` / `seal` / `freeze` → «раздел Замки».
- Порядок ключей: индексы → строки → символы; `'4294967295'` уже не индекс → «раздел Замки».
- Декораторы выполняются при вычислении объявления класса; современный вариант TypeScript и legacy-вариант с `experimentalDecorators` используют разные интерфейсы.
- Подсказки `toPrimitive`: `string`, `number`, `default` → «раздел Символы».
- Помощники `map`/`filter`/`take` на `Iterator.prototype` ленивые → «Протокол итератора».

</details>
