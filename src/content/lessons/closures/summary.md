# Замыкания и области видимости

`lessons/closures` · выжимка обновлена 2026-11-11 по тексту темы.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- `makeCounter()` возвращает функцию с доступом к переменной `count` своего вызова. Два вызова создают два независимых состояния: `a(), a(), b()` возвращают `1 2 1`.
- Замыкание — функция со ссылкой на окружение, где её создали. При поиске имени она идёт по цепочке `outer`, а не ищет переменную у вызывающего кода.
- Окружение сохраняется после возврата внешнего вызова, пока доступно через замыкания. Соседние функции могут читать и менять одну общую переменную.

</details>

<details>
<summary><b>Карта</b> — как объяснить поведение</summary>

- Если имени нет в текущем окружении, поиск продолжается во внешнем. Поэтому одинаковое имя `count` не объединяет разные вызовы `makeCounter`.
- Объявления обрабатываются до выполнения инструкций. У `var` до присваивания значение `undefined`; `let` и `const` до инициализации находятся в TDZ и не допускают чтения.
- `typeof` возвращает `"undefined"` для несуществующего имени, но бросает `ReferenceError` при чтении переменной в TDZ.
- Замыкание видит переменную в момент вызова, а не снимок её значения. Изменение переменной после создания функции влияет на результат её следующего вызова.
- Учебный интерпретатор строит окружения по шагам; ScopeLab отдельно исполняет ту же программу браузерным движком и сравнивает выводы. Нарисованные окружения — модель, а не снимок кучи.

</details>

<details>
<summary><b>Подвох</b> — где встречается</summary>

- Сохранённый обработчик может обращаться к переменным старого вызова: это устаревшее замыкание. Помогают пересоздание обработчика или чтение актуального значения из общего объекта.
- В `for (var …)` обработчики читают одну переменную после завершения цикла. В `for (let …)` у итераций свои переменные, а при переходе копируется текущее значение, включая изменения из тела.
- Замыкания дают приватное состояние хранилищу, фабрике, `once` и `memoize`. Для фабрики функции создаются на каждый объект; методы класса с `#`-полем обычно общие через прототип.
- Стрелка не получает собственный `this`: она использует `this` внешнего окружения.

</details>

<details>
<summary><b>Детали</b> — смотреть в дополнительных разборах</summary>

- Глобальное окружение обычного скрипта состоит из части, связанной с `window`, и отдельной таблицы лексических объявлений.
- Для примера `for (let i = 0; i < 3; i++)` точный счёт — пять окружений переменной: init и четыре окружения итераций, включая последнее с ложным условием. Это не значит, что браузер обязан создать пять физических объектов в куче.
- Стрелка из init сохраняет первую переменную, поэтому `peek()` может всё время возвращать `0`, пока копии меняются.
- V8 создаёт `BlockContext` для захваченной переменной итерации; без захвата такой объект может не понадобиться. Устройство Context и удержание лишних данных разобраны в «Памяти и GC».
- Тип `ReferenceError` нормативен, текст сообщения у движков различается.

</details>
