# Движок V8

`lessons/v8-engine` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** V8 исполняет JS и ускоряет часто выполняемый код на основе наблюдений за значениями.
- **Сквозной пример:** `function get(o) { return o.x; }`. Результат остаётся правильным для `{ x: 1 }` и `{ y: 0, x: 2 }`, но путь к полю в памяти различается.
- **Как работает:**
  1. Форма описывает набор и расположение полей объекта.
  2. Кеш у конкретного чтения `o.x` запоминает встреченные формы и способы получить поле. У другого места чтения свой кеш.
  3. Нижние ярусы собирают профиль. Maglev и TurboFan используют его, чтобы построить быстрый код под ожидаемые формы.
  4. Страж проверяет предположение перед быстрым чтением. Неожиданная форма может вызвать деоптимизацию: V8 восстанавливает исполнение без неверного предположения.
- **Зачем ярусы:** сложная компиляция тоже стоит времени. Ignition быстро начинает исполнение, Sparkplug дешёво строит машинный код, а оптимизирующие компиляторы окупаются на горячих функциях.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Со страницы не узнать состояние IC или ярус; время показывает следствие. В Node помогают снимок кучи и флаги V8 → «раздел Что видно».
- OSR, ленивый разбор, песочница V8 → «раздел Ярусы»; WebAssembly — в теме «WebAssembly».
- Дерево переходов форм, расширение представления поля, словарный режим после `delete` → «раздел Формы».
- Состояния кеша на месте чтения меняются только вперёд → «раздел Inline caches».
- Виды элементов: две оси, назад почти не возвращаются (исключение — `fill`) → «раздел Elements».
- Советы эпохи Crankshaft устарели → «раздел Мифы».
- Как врут микробенчмарки → «раздел Замеры».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Мегаморфизм ≠ деоптимизация: переход к пятой форме стоит одного отката, дальше откатов нет — компилятору просто не на чем строить.
- Удаление последнего поля форму не откатывает — объект уходит в словарь; форму сохраняет `obj.prop = undefined`.
- Опасен не одиночный откат, а откаты одной функции по кругу.
- Прогрев ускоряет второй замер через готовый код OSR, а не потому, что функция оптимизирована целиком.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `%DebugPrint`, `%HaveSameMap` работают только с `--allow-natives-syntax` (при запуске или `v8.setFlagsFromString`) → «раздел Что видно».
- `deopt-eager` против `deopt-lazy` → «раздел Ярусы».
- Поле: `Smi` → `Double` → `Tagged`, видно `--trace-generalization` → «раздел Формы».
- В модели V8 полиморфизм — до четырёх форм. Один стенд сопоставляет объяснения состояний, записанный замер Node 24 и отдельный запуск в браузере; время не подтверждает состояние кеша → «раздел Inline caches».
- `new Array(5)` — `HOLEY_SMI`, после `.fill(0)` — PACKED → «раздел Elements».
- Шаг `performance.now()`: 0.1 мс Chromium, 1 мс Firefox → «раздел Замеры».

</details>
