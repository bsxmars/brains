# Коллекции: Map, Set и словари

<details>
<summary><b>Ядро</b> — ключи и равенство</summary>

- Объект хранит свойства со строковыми или символьными ключами. Остальные ключи преобразуются; обычное чтение ищет и в прототипах. `Object.create(null)` убирает прототип, но сохраняет правила ключей объекта.
- `Map` хранит отдельные записи с ключами любого типа. `1` и `'1'` различаются; объект находится по той же ссылке даже после изменения его полей.
- `get` возвращает значение, `has` проверяет наличие. Сохранённое `undefined` и отсутствующий ключ дают одинаковый результат `get`.
- `Set` хранит уникальные значения. У него и `Map` действует SameValueZero: повторный `NaN` совпадает, `0` и `-0` — один ключ, разные объекты остаются разными.

</details>

<details>
<summary><b>Карта</b> — порядок и устройство</summary>

- `Map` и `Set` обходятся в порядке вставки. Перезапись сохраняет положение; удаление и новая вставка переносят запись в конец.
- Стандарт требует доступ в среднем быстрее полного перебора, но не предписывает конкретную хеш-таблицу или одинаковое время при любом размере.
- В V8 корзины сужают поиск по хешу, а массив записей сохраняет порядок. Внутри корзины проверяются сами ключи: хеши могут совпадать.
- Удаление оставляет пустое место; при перестройке V8 сохраняет поведение уже созданных итераторов. Внутренние имена — `OrderedHashMap` и `OrderedHashSet`.
- `WeakMap` связывает значение с объектом или незарегистрированным символом, не удерживая ключ этой записью. Перечисления и `size` нет; срок сборки не гарантирован.

</details>

<details>
<summary><b>Подвох</b> — что меняет результат</summary>

- `map[key]` — обычное свойство; записи читают и пишут через `get`/`set`. `JSON.stringify` и объектный спред записи не видят.
- Во время незавершённого обхода удалённая запись пропускается, новая может попасть в обход, а удалённая и вставленная снова — прийти повторно. Обновление текущего ключа через `delete` + `set` может создать бесконечный цикл; снимок `[...m]` ограничивает обход исходными записями.
- После `done: true` новые вставки не оживляют итератор.
- `Set` не объединяет объекты с одинаковыми полями. Для уникальности по id нужен ключ id в `Map`; последняя версия заменит предыдущую.
- `WeakSet` с отметками одного обхода надо создавать для каждого обхода. Локальный `Set` тоже подходит; слабый набор нужен, когда отметки живут дольше объектов.

</details>

<details>
<summary><b>Детали</b> — методы и преобразования</summary>

- `getOrInsert` получает уже вычисленное значение. `getOrInsertComputed` вызывает функцию только при отсутствии ключа.
- `union`, `intersection`, `difference`, `symmetricDifference` создают новый `Set`; исходные множества сохраняются. Проверки включения и пересечения возвращают `boolean`.
- Аргумент операций `Set` должен иметь `size`, `has`, `keys`: `Map` подходит, массив нужно преобразовать в `Set`.
- `Object.fromEntries` преобразует ключи в ключи свойств и может объединить разные записи. Формат JSON надо выбирать с учётом типов ключей.
- `Object.groupBy` возвращает объект без прототипа; `Map.groupBy` сохраняет типы ключей, в том числе объекты. В обеих версиях группы — массивы.

</details>
