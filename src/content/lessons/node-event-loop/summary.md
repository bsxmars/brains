# Цикл событий Node: фазы libuv

- Node исполняет обычный JavaScript в потоке своего event loop, а сеть, таймеры и часть внешней работы организует через libuv. Await сам по себе не переносит расчёт в другой поток.
- Фазы цикла и очереди nextTick и микрозадач — разные механизмы. В обычной границе Node-callback сначала обрабатывает nextTick, затем микрозадачи; начальное выполнение ESM имеет иной контекст.
- `setImmediate` связан с фазой check, таймеры — с наступлением заданного срока. Их порядок на верхнем уровне нельзя считать универсальным для всех условий.
- Файловые операции, некоторые DNS-вызовы, криптография и сжатие могут конкурировать за пул потоков. Это не то же самое, что отдельный JS-worker для каждой задачи.
- Процесс живёт, пока есть удерживающая работа: активные handles, запросы и завершение ресурсов. Promise без внешнего источника результата сам по себе не обязан удерживать процесс.
- Долгий callback и бесконечные nextTick или микрозадачи задерживают остальные события. Сокращайте синхронные части и ограничивайте очередь тяжёлой работы, а не только число HTTP-запросов.
