# Профилирование памяти

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- Снимок — граф сохранившихся объектов и ссылок одного изолята. Он помогает найти данные, которые программа продолжает хранить после завершения их работы.
- Выберите повторяемый сценарий, прогрейте приложение, сделайте одинаковые серии и сравните снимки. Третий снимок помогает отделить разовый рост от повторного.
- Comparison показывает прирост объектов и их собственного размера. Summary и Retainers помогают найти тяжёлые данные и удерживающие ссылки.
- Shallow size — собственный размер узла; retained size — он сам и данные, достижимые только через него. При втором независимом пути разрыв одной ссылки не освобождает данные.

</details>

<details>
<summary><b>Карта</b> — где продолжить разбор</summary>

- Метрики кучи, DOM и обработчиков — «График».
- Повторяемый сценарий и три снимка — «Процедура».
- Оборот и накопление, число объектов и размер — «Comparison».
- Доминатор, второй путь и арифметика retained — «Retained».
- Цепочки ссылок и удержание консолью — «Retainers».
- Момент и стек выделения, sampling и queryObjects — «Профили».
- Снятие и программное чтение файла — «Снимок из Node».

</details>

<details>
<summary><b>Подвох</b> — частые ошибки</summary>

- Растущий минимум после GC ещё не доказывает утечку: проверьте назначение данных и сопоставимость нагрузки. Утечка не обязана быть линейной или кратной числу повторов.
- Отсоединённый DOM-узел может храниться намеренно. Служебное имя вроде system / Context тоже не оправдывает повторный рост.
- У Uint8Array малая обёртка; данные могут быть отдельным native-узлом system / JSArrayBufferData. Сортируйте и по числу, и по размеру.
- Retained size предка уже включает поддерево: размеры вложенных строк нельзя складывать повторно.
- fill кладёт одну и ту же ссылку, Array.from может создать отдельный объект на каждом шаге.

</details>

<details>
<summary><b>Детали</b> — смотреть по необходимости</summary>

- Веса лестницы сняты на Node 24.11 без сжатия указателей; это условия замера, а не универсальные размеры объектов.
- Профиль sampling по умолчанию показывает дожившие выделения. Учёт уже собранных объектов включают отдельно через протокол.
- Снимок блокирует поток и требует памяти; файл не представляет весь rss процесса.
- Имена полей формата берут из метаданных снимка: формат зависит от V8.

</details>
