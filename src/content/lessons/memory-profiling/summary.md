# Профилирование памяти

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** порядок действий, который находит утечку в снимке кучи — графе живых объектов и ссылок между ними.
- **Зачем:** в снимке сотни тысяч объектов, в основном движка. Если просто листать их, утечку не найти.
- **Как работает:**
  1. График показывает, есть ли утечка: после сборки растут минимумы.
  2. Повторяемый сценарий ×N, три снимка, сравнение 3-го со 2-м.
  3. Comparison: подозреваемый — прирост `#Delta`, кратный числу прогонов.
  4. Summary → retained size → Retainers → звено вашего кода, ближайшее к корню.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Какие линии растут вместе (heap, DOM-узлы, обработчики), показывает вид утечки → «раздел График».
- Подготовка: инкогнито, очистить консоль, снять выделение `$0`, прогрев → «раздел Процедура».
- `# New`/`# Deleted` — оборот, `# Delta` — остаток; в Comparison нет retained → «раздел Comparison».
- Shallow против retained; доминатор; retained нельзя складывать → «раздел Retained».
- Имена рёбер в цепочке и консоль как держатель → «раздел Retainers».
- Четыре профиля вкладки Memory и `queryObjects` через протокол отладчика → «раздел Профили».
- Снимок из Node — это JSON, его можно разобрать скриптом → «раздел Снимок из Node».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Два независимых пути к объекту: разорвали один — освободилось 0 байт. Починено, только когда `#Delta` дошла до нуля.
- `fill({...})` кладёт один объект 500 000 раз, а не 500 000 объектов.
- `(compiled code)` и `(system)` растут вместе с приложением, это не утечка.

</details>
