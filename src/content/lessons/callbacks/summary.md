# Колбэки

`lessons/callbacks` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** функция, которую отдают чужому коду, чтобы тот вызвал её сам (инверсия управления).
- **Зачем:** так чужой код сообщает о результате; цена — когда, сколько раз, с чем и с каким `this` звать, куда уйдёт `throw`, решаете не вы.
- **Как работает:** передача функции сама по себе не создаёт асинхронность. При синхронном вызове активен стек вызывающего; при отложенном его кадр уже завершён. Канал результата и ошибок задаёт API. Промис фиксирует первый исход, но не запрещает исходному API повторять вызов колбэка.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Кто зовёт колбэк сразу, а кто потом, и где это закреплено спецификацией → «раздел Стек».
- Функция — объект с доступом к внешним переменным; передача против вызова; позиционные аргументы ломают `map(parseInt)` → «раздел Передача».
- Zalgo: момент вызова должен быть предсказуемым для потребителя; executor синхронен, `.then` асинхронен всегда → «раздел Zalgo».
- `this` определяется в момент вызова; способы привязки и их цена → «раздел this».
- Внешний try/catch не ловит бросок из отложенного колбэка; error-first и отдельное событие — соглашения API. Стек и глобальные обработчики — в «Ошибках и стеках», идентификатор запроса — в «Асинхронном контексте». Замыкание сохраняет данные и после завершения кадра → «раздел Ошибки».
- Исполняемый адаптер callback→Promise; первый ответ фиксируется, реакция выполняется позже. Подробное сравнение гарантий и проблем вложенности — дополнительный разбор → «раздел Гарантии».
- Колбэк, меняющий структуру, по которой его вызывают, портит чужой обход → «раздел Реентерантность».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Для removeEventListener нужны та же ссылка, тип события и capture. Повторный bind создаёт другую функцию; сохранённый listener снимается. once и сигнал отмены — другие способы завершить подписку.
- Слушатель, снятый во время рассылки: `EventEmitter` его ещё вызовет (идёт по копии), DOM `EventTarget` — нет.
- Без return после cb(err) выполнение продолжается. В показанном коде второй вызов не наступает: data.toString() бросает раньше. once этого не исправляет. `forEach` не ждёт `async`-колбэк.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `['1','2','3'].map(parseInt)` → `[1, NaN, NaN]` → «раздел Передача».
- `setTimeout(fn())`: Node бросает `ERR_INVALID_ARG_TYPE`, браузер исполняет результат как код → «раздел Тонкости».
- `emitter.on(..., { signal })` игнорирует сигнал; работают `events.addAbortListener` и `events.on` → «раздел Тонкости».
- bind не меняет this стрелки, но по-прежнему привязывает аргументы; повторный bind добавляет их после прежних.
- Замыкание не означает автоматического удержания всех локальных переменных. Общий Context V8 может сохранять значения, захваченные соседней функцией.
- `thisArg` у 11 методов, у `sort` нет, у `reduce` второй аргумент — начальное значение → «раздел Тонкости».
- Новые слушатели не входят в уже обходимый список, но обработчик предка, добавленный до всплытия, может участвовать в том же DOM-событии → «раздел Реентерантность».
- `util.promisify` превращает колбэк-функцию в промис-функцию → «раздел Гарантии».

</details>
