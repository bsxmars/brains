  ### Передача против вызова — разница в одну пару скобок

    `map` вызывает колбэк с **тремя** аргументами — элемент, индекс, массив, — а `parseInt`
    принимает два, и второй у него — основание системы счисления. Лечение — обёртка, которая
    передаёт только нужное: `.map(s => parseInt(s, 10))`.

  ### Какие решения остаются у вызывающего

  <IocBoundary rows={IOC_ROWS} />

  Функцию нельзя передать в другой поток обычным клонированием. `postMessage` в воркер копирует
  аргументы структурным клонированием, а функцию оно не копирует: колбэк в сообщении
  бросает `DataCloneError` ещё у отправителя. Что ещё не переживает копирование — [«Копирование
  и сериализация», раздел «Structured clone по шагам»](/js/serialization/#s4).

</Section>

  lead="Платёжная библиотека по ошибке позвала `onSuccess` дважды — и заказ оформлен два раза. Простой колбэк от такого не защищён ничем: сколько раз и когда его звать, решает чужой код. Промис даёт как раз те гарантии, которых у колбэка нет."

  `readTwice` вызвала колбэк дважды, но первый `resolve` зафиксировал результат промиса.
  Подписанная реакция получила только первый ответ и выполнилась асинхронно. Это гарантия
  промиса, а не ограничение числа вызовов исходного колбэка: побочные эффекты до `resolve`
  по-прежнему могли бы повториться.

  <CardGrid min={280} gap={14}>
    <Card tone="info" pad={16} radius={4} size={15.5}>

      **На промис можно подписаться и после его завершения.** Он хранит результат
      для поздних подписок. Обычный EventEmitter не воспроизводит прошедшие emit для нового
      слушателя. API на колбэках тоже может иметь кеш, но это дополнительная логика API,
      а не свойство переданной функции.

    </Card>
    <Card tone="warn" color="tone" pad={16} radius={4} size={15.5}>

      **«Вызовется хотя бы один раз» не обещает и промис.** Промис, который навсегда остался
      в ожидании (pending), пока на него есть ссылка, молча держит в памяти все реакции и их замыкания. Чтобы ограничить ожидание, можно использовать `Promise.race` с таймером.
      `AbortSignal.timeout` помогает только тому API, которое принимает и учитывает сигнал;
      сам по себе он не завершает произвольный промис.

    </Card>

  [«Отмена: AbortController и AbortSignal»](/js/abort-controller/).

  В Node функцию с колбэком можно превратить в функцию с промисом одной строкой:
  `util.promisify(fs.readFile)` возвращает функцию, которая отдаёт промис, а `err` из колбэка
  превращает в отказ. `util.callbackify` делает обратное. Обёрнутая функция сразу получает
