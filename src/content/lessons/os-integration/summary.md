# Страница и система: экран, «Поделиться», значок, оплата

`lessons/os-integration` · выжимка по актуальному тексту темы, 2026-11-11.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** четыре API, которыми страница просит операционную систему: `wakeLock`, `share`, `setAppBadge`, `PaymentRequest`.
- **Зачем:** экран не гаснет, данные уходят в мессенджер через системное меню, число непрочитанных видно на иконке, оплата — окном браузера без формы карты.
- **Как работает:**
  1. Проверить API и безопасный контекст: HTTPS и доверенный localhost подходят, обычный удалённый HTTP-источник — нет.
  2. Web Share и платёжный интерфейс связывают с активацией пользователя. Badging и Wake Lock имеют другие условия. Около5с — записанный срок активации на стенде, а не гарантия API.
  3. Поймать отказ по `err.name` и показать запасной путь.
  4. Чужому iframe разрешить поимённо: `allow="payment; screen-wake-lock; web-share"`.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Намерение wanted и действующий замок различаются. Возврат видимости может потребовать нового request с обработкой отказа → «раздел Wake Lock».
- `canShare` и запасной путь через копирование ссылки → «раздел Поделиться».
- Значок виден только у установленного приложения; при закрытой странице — из Service Worker → «раздел Значок».
- Пять шагов оплаты и почему ставят кнопку провайдера → «раздел Оплата».
- `navigator.userActivation`, `allow`, `Permissions-Policy` → «раздел Жест и iframe».
- Таблица наличия в движках, манифест → «раздел Есть ли API».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Ошибка серверного подтверждения после show не должна оставить PaymentResponse незавершённым. complete сообщает результат интерфейсу; деньги этим вызовом не списываются.
- Отказ записи в буфер обмена требует ещё одного запасного пути: например, видимой ссылки для ручного копирования.
- `share()` забирает жест: второе меню из того же клика не откроется.
- `setAppBadge` во вкладке выполняется и ничего не показывает.
- На стенде WebKit отклонял Wake Lock без активации. При возврате вкладки нужно обработать этот отказ, сохранив возможность повторить по кнопке.
- В записанном сравнении трёх движков заголовок screen-wake-lock=() соблюдал только Chromium; результаты не заменяют проверку конкретной возможности.
- В Playwright `page.evaluate` — уже жест, вкладки всегда видимы, а headless shell — не Chrome.

</details>
