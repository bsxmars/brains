# Общая память и Atomics

`lessons/atomics` · выжимка по актуальному тексту темы, 2026-11-11.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** операции над общим буфером, которые неделимы и задают порядок между потоками.
- **Зачем:** без них прибавки из разных потоков теряются, а флажок «готово» бывает виден раньше данных.
- **Как работает:**
  1. Одно число — атомарной операцией: `Atomics.add`, `compareExchange`.
  2. Пачку данных — обычными записями, а флажок — `Atomics.store`; читатель видит установленный флажок через `Atomics.load` и читает опубликованные данные. Писатель их больше не меняет.
  3. Ждать — `Atomics.wait` и `notify` с повторной проверкой условия; на главном потоке браузера — только `waitAsync`.
  4. Несколько полей сразу — под замком из `compareExchange` и `wait`.

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `Atomics.wait` на главном потоке браузера — `TypeError`; в Node разрешён, и код ломается при переносе.
- Ноль ошибок в прогоне не доказывает корректность. ARM-частоты в теме относятся только к указанному сценарию; x86 тоже не заменяет гарантии модели памяти JS.
- Сам `store` ожидающего не будит, а `notify` не меняет флажок и не сохраняет уведомление для будущего ожидания.
- `waitAsync` возвращает объект `{ async, value }`: value бывает строкой или промисом.
- Дробных атомарных операций нет; `BigInt64Array` хочет `1n`.
- Спин-цикл занимает ядро целиком.

</details>
