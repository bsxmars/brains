# Память и GC

`lessons/memory-gc` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** сборщик удаляет объекты, до которых нельзя дойти по ссылкам от корней (глобальный объект, стек, модули, таймеры, подписки, нативный код); mark-and-sweep, счётчиков ссылок в V8 нет.
- **Зачем:** «нужен ли объект» доказать невозможно, а «достижим ли» — можно; утечки живут в щели «достижим, но не нужен».
- **Как работает:** новый объект — сдвиг указателя в молодом полупространстве → Scavenge копирует выживших в другую половину → переживший сборки переезжает в старое поколение → там его оплачивает каждая Major GC (Mark-Compact).

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Из JS момент сборки не виден; со страницы — только `WeakRef.deref()` и `FinalizationRegistry`, в Node — `process.memoryUsage()` и модуль `v8` → «раздел Что наблюдаемо».
- Дорого не создать объект, а не дать ему умереть; снижать надо давление на сборщик (долю выживших), а не на аллокатор → «раздел Путь объекта».
- Orinoco: пометка по частям и в фоне, параллельные паузы, барьер записи и трёхцветная пометка; у других движков свои барьеры → «раздел Путь объекта».
- Шесть классов утечек: слушатель, таймер, оторванный DOM, кеш без границ, глобальные, замыкания (плюс незакрытый `MessagePort`) → «раздел Утечки».
- Замыкание держит весь Context скоупа, общий для всех функций этого скоупа; в Context попадают только захваченные переменные, прямой `eval` тащит туда всё, отладчик не видит незахваченное → «раздел Замыкания».
- Запись WeakMap — эфемерон: ссылка из значения на ключ не утечка, утечка — если значение держат снаружи → «раздел Слабые ссылки».
- `using`/`DisposableStack` освобождают ресурс в известной точке; утечку видно по растущей нижней огибающей графика → «раздел using», «раздел Диагностика».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- Цель `WeakRef` живёт до конца задачи (KeptObjects): перед `gc()` нужна новая задача (`setTimeout`/`setImmediate`), микрозадачи мало.
- `gc()` утечку не лечит: достижимое он заново пометит живым.
- `removeEventListener(..., fn.bind(this))` молча не снимает слушатель; пул объектов сегодня чаще вредит.
- Безобидный колбэк держит тяжёлый объект, если его захватила соседняя функция того же вызова.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- Порог больших объектов ~128 КБ; их не копируют, адрес не меняется → «раздел Путь объекта».
- Полупространство: 64 МБ (Node 24.11) / 32 МБ (26.8); `heap_size_limit` = `--max-old-space-size` + 3 × полупространство → «раздел Путь объекта».
- 13 пространств кучи, `map_space` нет → «раздел Что наблюдаемо».
- Барьеры: Дейкстры (V8), Юасы (SpiderMonkey), Стила (JavaScriptCore) → «раздел Путь объекта».
- `queryObjects`: alone 0, sibling 10, withEval 10, nulled 0 → «раздел Замыкания».
- 20 подписок: 156 МБ с соседом `peek`, 3 МБ без него → «раздел Замыкания».
- `(0, eval)` исполняет строку в глобальном окружении и Context не тянет → «раздел Замыкания».
- `delete`: ~65 → ~480 байт на объект (dictionary mode) → «раздел Тонкие места».
- `SuppressedError`, `stack.use/defer/adopt/move` → «раздел using».

</details>
