# Отмена: AbortController и AbortSignal

`lessons/abort-controller` · выжимка обновлена 2026-11-11 по тексту темы.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- Контроллер даёт право вызвать отмену; сигнал передаётся исполнителю. Сигнал сам не прерывает JavaScript и не изменяет уже завершённый промис.
- `abort(reason)` навсегда меняет состояние и синхронно вызывает слушателей. Поздняя подписка не получает прошедшее событие.
- Своя операция проверяет сигнал до старта, подписывается на время работы и очищает ресурсы при любом исходе. Отменить delay — значит снять таймер, а не только отклонить промис.
- Готовый старый ответ может успеть раньше отмены. Если показывать его уже нельзя, после await нужна проверка сигнала перед применением результата.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- `attachSearch` создаёт контроллер на каждый ввод, отменяет предыдущий запрос, проверяет HTTP-ответ и актуальность данных, возвращает функцию очистки.
- `AbortSignal.any` отменяется вслед за первым источником. При уже отменённых входах берётся первый из них по порядку массива. Повторная отмена причину не заменяет.
- `timeout` и пользовательский сигнал можно объединить. Когда оба уже отменены, два флага aborted не показывают победителя: важна сохранённая причина combined.
- fetch сначала возвращает Response с заголовками. Отмена позже отклоняет чтение тела; заголовки и полностью прочитанное тело — разные стадии.
- Сервер сам решает, останавливать ли работу при разрыве соединения. Клиентская отмена не откатывает записанные данные.
- Общий запрос отменяется после ухода всех потребителей. Новый потребитель после последнего ухода должен начать новый запрос, а не получить уже отменяемый.

</details>

<details>
<summary><b>Подвох</b> — частые ошибки</summary>

- once снимает обработчик при событии. Если работа успешно закончилась без отмены, обработчик всё равно нужно удалить.
- Отмена после resolve не меняет промис, но забытый слушатель ещё может выполнить побочный эффект.
- `signal.aborted` описывает состояние задачи, но не доказывает, что именно отмена вызвала пойманную ошибку. Для устаревшей UI-задачи результат можно намеренно отбросить; для диагностики нужен контракт API.
- reason может быть строкой, null или другим значением. Только undefined заменяется стандартным AbortError.
- У EventEmitter.on нет опции signal. Для такого API нужна явная очистка или events.addAbortListener.

</details>

<details>
<summary><b>Детали</b> — смотреть по необходимости</summary>

- any раскрывает зависимости до исходных сигналов; причины зависимых выставляются раньше рассылки событий. Порядок событий зависимых в Node 26 отличается от записанного порядка Chromium и Node 24.
- Учебная модель исполняется рядом с настоящими классами браузера. У неё сильные Set для зависимых сигналов; реальные реализации имеют другие правила удержания.
- Слабые ссылки не означают, что зависимый сигнал со слушателем обязательно исчезнет. Очистка слушателя важна и при any.
- В опыте HTTP/1.1 разрывается незавершённое соединение; HTTP/2 закрывает поток RST_STREAM с CANCEL, сохраняя соединение.
- API Node могут отклонять своим AbortError с ABORT_ERR и исходной причиной в cause; fetch использует причину сигнала.
- Таймер AbortSignal.timeout в Node не удерживает процесс. Это отличается от обычного setTimeout учебной реализации.

</details>
