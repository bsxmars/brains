# Отмена: AbortController и AbortSignal

`lessons/abort-controller` · выжимка составлена с ИИ 2026-10-29 по тексту темы. Ключ ответа: сначала расскажи тему сам за 2 минуты, не глядя, потом открывай.

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** договорённость двух объектов: контроллер решает, что работа не нужна, а сигнал сообщает об этом исполнителям.
- **Зачем:** промис — это результат, а не операция, и отменить его нельзя. Остановить можно только саму работу, причём право отменить надо отделить от права узнать об отмене.
- **Как работает:** `abort(reason)` записывает причину и синхронно, один раз, зовёт слушателей `abort`. Как остановиться, каждый получатель решает сам: `fetch` рвёт соединение, `spawn` убивает процесс. Своя функция остановится, только если написана по правилу «проверь — подпишись — отпишись».

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- У сигнала нет метода отмены, поэтому его можно раздавать кому угодно. Один сигнал заменяет полдюжины способов отписки → «раздел Контроллер и сигнал».
- `any()` подписывается прямо на корни, а не строит цепочку. Зависимые сигналы получают причину раньше, чем приходят события → «раздел Устройство».
- Зависимый сигнал со слушателем держится в памяти, пока жив хотя бы один неотменённый источник → «раздел Устройство».
- Об отмене `fetch` сервер узнаёт только по закрытию ответа и сам решает, бросать ли работу. Отмена ничего не откатывает → «раздел fetch».
- Кто отменил, видно по `aborted` у сигналов, а не по имени ошибки → «раздел timeout и any».
- `fetch` и API Node отклоняются по-разному → «раздел Свой код».
- Общий запрос «отменить, когда ушли все» пишется счётчиком → «раздел Гонка».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `{ once: true }` — не отписка. Если отмены не было, слушатель остаётся навсегда: 100 вызовов оставляют 100 слушателей, и Node не предупреждает.
- Если подписаться после отмены, событие не придёт и промис повиснет навсегда. Поэтому сначала `throwIfAborted()`, потом подписка.
- Отмена после завершения ничего не меняет, но слушатель всё равно срабатывает. После `await` проверь `signal.aborted`.

</details>

<details>
<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- На `AbortError` заменяется только `undefined`. `abort(null)` даёт причину `null`, а строка бросается как есть → «раздел Контроллер и сигнал».
- В `any()` побеждает первый отменившийся по времени. Если в списке уже есть отменённые, побеждает первый из них по порядку в массиве → «раздел timeout и any».
- В HTTP/2 отмена шлёт `RST_STREAM` с кодом `CANCEL` (8), соединение живёт. В HTTP/1.1 соединение закрывается → «раздел fetch».
- API Node отклоняются своим `AbortError` с `code: 'ABORT_ERR'`, причина лежит в `cause`. `fetch` отдаёт причину как есть → «раздел Свой код».
- Таймер `AbortSignal.timeout()` в Node снят с учёта цикла (`unref`), и процесс может выйти, не дождавшись отмены: ES-модуль с `await` верхнего уровня — с кодом 13, CommonJS — молча с кодом 0 → «раздел timeout и any».
- Ошибка в слушателе в Node становится `uncaughtException` на следующем тике. `getMaxListeners(signal)` равен 0 → «раздел Тонкие места».

</details>
