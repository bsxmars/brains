# Память в Node

<details>
<summary><b>Ядро</b> — что нужно помнить</summary>

- **Что это:** `rss` — вся память процесса, куча JS — лишь один блок в ней.
- **Зачем:** процесс убивает ядро по `rss`; инструмент выбирают по тому, что растёт.
- **Как работает:**
  1. Логируют все пять полей `memoryUsage()`.
  2. Растёт `heapUsed` — снимок; `external` — буферы и стримы; только `rss` — фрагментация, нативный код.
  3. Утечку JS видно по числу после стрелки у `Mark-Compact`.
  4. Потолок кучи ставят ниже лимита пода — чтобы падение оставило лог.

</details>

<details>
<summary><b>Карта</b> — знать, что это существует</summary>

- Разрыв между `rss` и суммой полей — норма → «раздел Пять полей».
- Четыре поля считаются по потоку, `rss` — по процессу → «раздел Развилка».
- `rss` не падает: V8 придержал страницы, аллокатор — арены, или течёт вне кучи → «раздел Развилка».
- `mu` — доля времени вашего кода → «раздел trace-gc».
- `heap out of memory` против молчаливого `OOMKilled` → «раздел Лимиты».
- Потолок воркера — `resourceLimits` → «раздел Лимиты».
- Снимок пишется синхронно и раздувает память; `--inspect` — только localhost → «раздел Снимки».

</details>

<details>
<summary><b>Подвох</b> — крайние случаи и частые ошибки</summary>

- `--max-old-space-size` не ограничивает память процесса; поднятый потолок приближает падение.
- Node 24 на поде 256 Mi берёт потолок кучи больше пода — проверять изнутри контейнера.
- Утечку контекстов показывает `number_of_native_contexts`, не `detached`.

</details>

<summary><b>Детали</b> — не учить, смотреть в теме</summary>

- `MALLOC_ARENA_MAX` в замере `rss` не снизил → «раздел Развилка».
